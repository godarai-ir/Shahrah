# تحلیل مرجع: Dust، Langdock، Claude Enterprise

این سند ساختار اطلاعاتی سه محصول هم‌دسته را خلاصه می‌کند تا روشن شود کدام الگو را برای گدارAI برمی‌داریم و کدام را نه. طبق `PRODUCT.md` این سه فقط مرجع طراحی‌اند و در سایت نام برده یا مقایسه نمی‌شوند.

> منبع: Langdock و صفحهٔ Claude Enterprise در ۳۰ مهر ۱۴۰۵ (۲۰۲۶-۱۰-۲۲) خوانده شدند. dust.tt در همین تاریخ به‌دلیل خطای گواهی TLS در دسترس ابزار نبود؛ ساختار Dust از شناخت پیشین سایت و مرجع ثبت‌شده در `DESIGN.md` آمده است و پیش از مرحلهٔ ۲ باید یک بار در مرورگر بازبینی شود.

## Dust (مرجع بصری اصلی)

- **منوی اصلی:** محصول (پلتفرم، ایجنت‌ها، اتصال‌ها، امنیت)، راهکارها بر اساس تیم (فروش، پشتیبانی، بازاریابی، مهندسی، داده، منابع انسانی، حقوقی)، مشتری‌ها، منابع، قیمت‌گذاری. دو CTA ثابت: شروع رایگان و رزرو دمو.
- **صفحهٔ اصلی:** Hero با تیتر بزرگ و تصویر واقعی محصول، نوار لوگو، بخش‌های تک‌ایده با پنل‌های رنگی ملایم، تب‌های کاربرد بر اساس تیم، بخش امنیت سازمانی، داستان مشتری با عدد، باند تیرهٔ پایانی.
- **صفحه‌های تیم:** هر تیم یک صفحه: Hero با کار واقعی همان تیم، چند سناریو، اتصال‌های مرتبط، نقل‌قول، CTA.
- **امنیت:** صفحهٔ مستقل با تعهدهای داده (آموزش ندیدن مدل روی داده)، گواهی‌ها، کنترل دسترسی، میزبانی داده.
- **قیمت‌گذاری:** چند پلن ساده به ازای هر کاربر، Enterprise با تماس.

## Langdock

- **منوی اصلی:** Platform (Chat، Workflows، Agents، Integrations، API، Models)، Learn (مستندات، داستان مشتری، Changelog، Trust center، کتاب راهنمای پذیرش AI)، About، و پیوندهای سطح‌اول Security، Enterprise، Pricing.
- **صفحهٔ اصلی:** Hero «The Platform for AI Adoption»، نوار لوگو، نقل‌قول، کارت‌های محصول (Chat تا API)، شش ستون («Model agnostic»، «Security-first»، «Deployable anywhere» و …)، راهنمای قدم‌به‌قدم پذیرش، داستان‌های ویدئویی، CTA آزمایش رایگان.
- **فوتر:** نوار اعتماد (امنیت، استقرار، GDPR)، گروه‌های Platform / Learn more / Company / Legal.
- **CTA:** آزمایش رایگان ۷ روزه بدون کارت، و Talk to sales.

## Claude Enterprise

- **منوی اصلی:** Product، Developers، Enterprise (Departments، Industries، Customers)، Resources، Pricing.
- **ترتیب صفحه:** Hero با دو CTA (پلن سازمانی / ساخت روی پلتفرم)، نقل‌قول و لوگو، «Built for enterprise» با چک‌لیست کنترل‌ها (SSO، SCIM، Audit logs، RBAC، Spend controls، Data retention)، «دو راه استفاده» (اپ برای کارکنان / API برای سازندگان)، مجموعهٔ محصول، اتصال‌ها، تب کاربرد بر اساس تیم، قیمت، داستان مشتری، FAQ سه‌گروهی (امنیت، قابلیت، شروع)، منابع، CTA پایانی.

## آنچه گدارAI دارد و این سه ندارند

ساختار سایت باید برای این‌ها جای مشخص بسازد، نه آن‌ها را در فوتر پنهان کند:

1. **گاردریل معنایی** به‌عنوان سازوکار اصلی امنیت (نه فقط «Security-first» کلی).
2. **مدیریت و کاهش هزینه** به‌عنوان یک تمایز مستقل با صفحهٔ خودش (بودجه، مسیریابی به مدل ارزان‌تر، حافظهٔ نهان، پرداخت تومانی).
3. **پرداخت تومانی و دسترسی پایدار به مدل‌های خارجی.**
4. **استقرار On-Premise** برای سازمان بزرگ.
5. **فارسی و راست‌به‌چپ** از رابط تا پشتیبانی.
6. **درگاه مدل‌های زبانی** به‌عنوان محصول دوم هم‌وزن، نه فقط یک API جانبی.
