# تشخیص Secret

`secrets_detection` برای تشخیص یا ماسک‌کردن secretهای رایج در متن استفاده می‌شود. این گاردریل یک مجموعه pattern داخلی دارد و برای زمانی مناسب است که نمی‌خواهید token، کلید خصوصی یا credentialهای شناخته‌شده وارد مدل شوند یا در پاسخ نهایی دیده شوند.

## چه زمانی استفاده کنیم؟

از این گاردریل برای کاهش ریسک نشت secret در prompt، پاسخ مدل یا workflowهای agentic استفاده کنید.

نمونه use caseها:

- ماسک‌کردن Bearer token در prompt
- جلوگیری از نمایش private key در پاسخ مدل
- پیدا کردن JWT یا API keyهای رایج در خروجی
- محافظت از log و trace در مسیرهایی که متن بعد از mutation ثبت می‌شود

## رفتار اجرایی

این نوع از هر دو عملیات پشتیبانی می‌کند:

| operation | رفتار |
| --- | --- |
| `validate` | اگر secret رایج match شود، check ناموفق می‌شود. |
| `mutate` | matchها با `redaction_text` جایگزین می‌شوند. |

در حالت `mutate`، اگر match پیدا شود status برابر `mutated` ثبت می‌شود و متن تغییر یافته به مسیر بعدی می‌رود.

## الگوهای داخلی

در implementation فعلی، این دسته‌ها بررسی می‌شوند:

- Bearer token با طول حداقل ۱۶ کاراکتر
- tokenهای سه‌بخشی شبیه JWT
- private key با blockهای `BEGIN ... PRIVATE KEY`
- AWS access key با prefix `AKIA`
- کلیدهای شبیه OpenAI با prefix `sk-`

این فهرست ثابت است و از config جداگانه برای افزودن pattern جدید استفاده نمی‌کند. برای pattern سفارشی از [Regex](/guardrails-regex) استفاده کنید.

## تنظیمات

| فیلد | نوع | اجباری | توضیح |
| --- | --- | --- | --- |
| `redaction_text` | `string` | خیر | متن جایگزین در حالت `mutate`. مقدار پیش‌فرض `[REDACTED]` است. |

## نمونه تعریف برای ورودی

```json
{
  "slug": "mask-secrets-input",
  "name": "Mask secrets in prompts",
  "type": "secrets_detection",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "redaction_text": "[REDACTED_SECRET]"
  }
}
```

## نمونه تعریف برای خروجی

```json
{
  "slug": "no-secrets-output",
  "name": "Block secrets in model output",
  "type": "secrets_detection",
  "operation": "validate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {}
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/mask-secrets-input"]}
```

یا برای خروجی:

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/no-secrets-output"]}
```

## selector آماده

موتور پیش‌فرض selector زیر را دارد:

```text
guardrails/secrets-detection
```

این selector با operation داخلی `mutate` کار می‌کند و matchها را با `[REDACTED]` جایگزین می‌کند.

## محدودیت‌ها

- این گاردریل همه انواع secret را نمی‌شناسد.
- secretهای domain-specific باید با [Regex](/guardrails-regex) پوشش داده شوند.
- tokenهایی که عمدا obfuscate شده‌اند ممکن است match نشوند.
- output guardrail در حالت streaming پشتیبانی نمی‌شود.
