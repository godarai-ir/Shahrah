# تست APIها با Postman

در پایان این راهنما، کالکشن رسمی Postman گدارAI را از GitHub دریافت می‌کنید، آن را برای فضای کاری خود تنظیم می‌کنید و تست‌های یک API یا کل ماتریس قابلیت‌ها را اجرا می‌کنید.

این کالکشن یک مجموعه آزمون رگرسیون و قرارداد برای API رسمی OpenAI است. همان تست‌ها می‌توانند مستقیماً روی OpenAI یا از مسیر گدارAI اجرا شوند؛ فایل محیط (Environment) انتخاب‌شده، نشانی پایه، احراز هویت و نگاشت مدل‌ها را تعیین می‌کند.

:::info آمار نسخه فعلی

آمار این صفحه از `provider-manifest.json` در [مخزن عمومی کالکشن‌های Postman گدارAI](https://github.com/godarai-ir/godarai-postman-collections) استخراج شده است. این فایل در `2026-08-04` تولید شده و تاریخ بازبینی منبع API در آن `2026-08-03` است.

:::

## فایل‌های اصلی مخزن

| فایل | کاربرد |
| --- | --- |
| `collections/OpenAI - Official Capability Matrix (Direct or via GodarAI).postman_collection.json` | کالکشن اصلی شامل درخواست‌ها، اسکریپت‌های پیش از درخواست و بررسی‌های خودکار |
| `OpenAI Official - Direct.postman_environment.json` | اجرای مستقیم با `target=openai` |
| `OpenAI Official - via GodarAI.postman_environment.json` | اجرای همان قراردادها با `target=godarai` |
| `provider-manifest.json` | فهرست ماشین‌خوان مدل‌ها، نقطه‌های پایانی، targetها، سطح‌های سرویس، سطح‌های استدلال و دروازه‌های قابلیت |
| `scripts/validate-collection.mjs` | اعتبارسنجی ساختار کالکشن و سازگاری قابلیت‌های مدل‌ها |

مخزن هیچ کلید دسترسی یا اعتبارنامه واقعی نگهداری نمی‌کند. فایل محیط گدارAI نیز ۲۱ کلید مدل را دارد، اما مقدار نگاشت آن‌ها در نسخه عمومی عمداً خالی است.

## پیش‌نیازها

- برنامه Postman یا دسترسی به نسخه وب آن
- دسترسی به یک فضای کاری گدارAI
- یک [توکن دسترسی معتبر](/guides/api-keys)
- شناسه محیط اختصاصی سازمان برای سرآیند `x-godarai-tenant`
- نام کامل مدل (FQN) برای هر مدلی که می‌خواهید تست کنید؛ برای تفاوت شناسه‌ها، [شناسه مدل‌ها](/model-identifiers) را بخوانید
- فایل نمونه (Fixture) و دسترسی لازم برای تست‌های فایل، صوت، تصویر، Batch یا Fine-tuning، اگر آن گروه‌ها را فعال می‌کنید

## ۱. مخزن را دریافت و فایل‌ها را وارد کنید

[مخزن `godarai-postman-collections`](https://github.com/godarai-ir/godarai-postman-collections) را باز و با گزینه `Code > Download ZIP` دریافت کنید، یا با Git یک نسخه محلی بسازید:

```bash
git clone https://github.com/godarai-ir/godarai-postman-collections.git
cd godarai-postman-collections
```

اگر فایل ZIP را گرفته‌اید، ابتدا آن را از حالت فشرده خارج کنید. سپس در Postman گزینه `Import` را بزنید و این دو فایل را وارد کنید:

1. `collections/OpenAI - Official Capability Matrix (Direct or via GodarAI).postman_collection.json`
2. `OpenAI Official - via GodarAI.postman_environment.json`

Postman فایل کالکشن و فایل محیط را هنگام `Import` تشخیص می‌دهد. جزئیات روش واردکردن فایل در [راهنمای رسمی Postman](https://learning.postman.com/docs/getting-started/importing-and-exporting/importing-data/) آمده است.

نتیجه مورد انتظار: کالکشن `OpenAI - Official Capability Matrix (Direct or via GodarAI)` و محیط `OpenAI Official - via GodarAI` در فضای کاری Postman دیده می‌شوند.

## ۲. محیط گدارAI را تنظیم کنید

محیط `OpenAI Official - via GodarAI` را باز کنید و این متغیرها را مقدار بدهید:

| متغیر | مقدار |
| --- | --- |
| `godarai_base_url` | نشانی API فضای کاری همراه با `/v1`؛ برای نمونه `https://YOUR_WORKSPACE.godarai.ir/v1` |
| `godarai_api_key` | کلید دسترسی گدارAI |
| `godarai_tenant_slug` | شناسه محیط اختصاصی سازمان |
| `godarai_model_map_json` | نگاشت شناسه رسمی OpenAI به FQN مدل متناظر در گدارAI |

نمونه نگاشت برای اجرای تست‌های سه مدل:

```json
{
  "gpt-4.1": "YOUR_GPT_4_1_MODEL_FQN",
  "gpt-4.1-mini": "YOUR_GPT_4_1_MINI_MODEL_FQN",
  "gpt-image-2": "YOUR_GPT_IMAGE_2_MODEL_FQN"
}
```

برای اجرای کامل ماتریس باید هر ۲۱ مقدار را به مدل واقعی متناظر نگاشت کنید. اگر FQN یک مدل خالی یا ناموجود باشد، مورد آزمون مربوط به آن با وضعیت `BLOCKED` متوقف می‌شود و کالکشن مدل دیگری را به‌عنوان مسیر جایگزین انتخاب نمی‌کند.

:::warning نگهداری امن کلید

کلید دسترسی را فقط به‌صورت مقدار محلی یا secret در Postman نگه دارید. فایل محیط دارای secret را export یا commit نکنید و نتیجه‌های اجرا را پیش از اشتراک‌گذاری از نظر سرآیندها، شناسه درخواست، شناسه محیط اختصاصی سازمان و FQNها بررسی کنید.

:::

## ۳. تست‌های پیش‌نیاز را اجرا کنید

1. محیط `OpenAI Official - via GodarAI` را از انتخاب‌گر محیط در بالای Postman انتخاب کنید.
2. در بخش `Collections`، گروه `00 - Preflight & Discovery` را باز کنید.
3. گزینه `Run` را بزنید و اجرای دستی (`Run manually`) را انتخاب کنید.
4. بررسی کنید محیط درست انتخاب شده باشد و اجرا را شروع کنید.

این گروه دسترسی به API، فهرست مدل‌ها و نگاشت مدل‌های موردنیاز را بررسی می‌کند. راهنمای کامل Collection Runner در [مستندات رسمی Postman](https://learning.postman.com/docs/tests-and-scripts/running-collections/intro-to-collection-runs/) در دسترس است.

نتیجه مورد انتظار: درخواست‌های مربوط به مدل‌های پیکربندی‌شده موفق می‌شوند و شناسه درخواست گدارAI در `x-godarai-request-id` یا `x-trace-id` ثبت می‌شود.

## ۴. گروه API موردنظر را اجرا کنید

پس از موفقیت تست‌های پیش‌نیاز، ابتدا فقط پوشه API موردنظر را اجرا کنید. برای نمونه، برای تست فراخوانی‌های متنی گروه `11 - Chat Completions` را در Collection Runner انتخاب کنید.

کالکشن برای هر مورد آزمون این کارها را انجام می‌دهد:

1. `target`، نشانی پایه، کلید دسترسی و مدل متناظر را آماده می‌کند.
2. پیش‌نیازهای همان مورد، از جمله دروازه قابلیت و فایل نمونه لازم، را بررسی می‌کند.
3. درخواست را به نقطه پایانی گدارAI می‌فرستد.
4. کد وضعیت مجاز و بخش‌های کلیدی قرارداد پاسخ را با بررسی‌های خودکار می‌سنجد.
5. شناسه درخواست یا علت اجرا نشدن را برای عیب‌یابی ثبت می‌کند.

در نتیجه اجرا:

- `Passed` یعنی بررسی‌های خودکار تعریف‌شده برای آن درخواست موفق بوده‌اند.
- `Failed` یعنی دست‌کم یکی از انتظارهای کد وضعیت یا قرارداد پاسخ برقرار نبوده است.
- `BLOCKED` یا `SKIPPED` یعنی پیش‌نیاز اجرا فراهم نیست؛ علت را در متغیر `last_skip_reason` بررسی کنید.

موفق‌شدن تست‌های منفی به معنی دریافت خطای مورد انتظار است. برای نمونه، درخواست با مدل ناشناخته باید رد شود؛ پاسخ موفق به چنین درخواستی نقض قرارداد محسوب می‌شود.

## بررسی ایستای فایل‌های مخزن

فرمان زیر ساختار کالکشن و سازگاری سطح‌های سرویس و استدلال با ماتریس قابلیت مدل‌ها را بررسی می‌کند:

```bash
pnpm install --frozen-lockfile
pnpm run check
```

این فرمان درخواست زنده به API نمی‌فرستد و جای اجرای Collection Runner را نمی‌گیرد. از آن پس از تغییر کالکشن، `provider-manifest.json` یا نگاشت قابلیت مدل‌ها استفاده کنید.

## رفع مشکل‌های رایج

### بیشتر تست‌ها `BLOCKED` می‌شوند

مقدارهای `godarai_model_map_json` را بررسی کنید. هر شناسه رسمی باید به FQN واقعی و مجاز همان مدل در فضای کاری نگاشت شود. علت دقیق آخرین مورد متوقف‌شده در `last_skip_reason` ثبت می‌شود.

### پاسخ `401` یا `403` دریافت می‌کنم

`godarai_api_key`، مقدار `godarai_tenant_slug` و دسترسی توکن به مدل را بررسی کنید. اگر توکن منقضی یا لغو شده است، یک [کلید دسترسی تازه](/guides/api-keys) بسازید.

### همه درخواست‌ها خطای مسیر می‌گیرند

مقدار `godarai_base_url` باید نشانی API باشد و با `/v1` پایان یابد. از قرار دادن مسیر نقطه پایانی، مانند `/chat/completions`، داخل این متغیر خودداری کنید.

### تست فایل، صوت یا تصویر اجرا نمی‌شود

متغیر فایل نمونه متناظر، مانند `sample_audio_path` یا `sample_image_path`، و دروازه قابلیت مربوط را تنظیم کنید. مسیر فایل باید برای محیطی که Postman در آن اجرا می‌شود قابل دسترسی باشد.

### شمار تست‌های اجراشده کمتر از ۶۵۱ است

این رفتار با تنظیمات پیش‌فرض طبیعی است. تست‌های پشت دروازه قابلیت یا فاقد مدل و فایل نمونه معتبر اجرا نمی‌شوند. عدد ۶۵۱ اندازه کامل ماتریس است، نه تعداد تست‌هایی که بدون تنظیم اختیاری حتماً درخواست زنده می‌فرستند.

## گام بعدی

- برای شناخت قرارداد هر نقطه پایانی، [APIهای پشتیبانی‌شده](/supported-apis) را بخوانید.
- برای مقایسه نتیجه کالکشن با ترافیک ثبت‌شده، [لاگ درخواست‌ها](/observability-logs) و [ردیابی درخواست‌ها](/observability-traces) را بررسی کنید.
- برای گزارش مشکل در خود کالکشن، در [مخزن GitHub](https://github.com/godarai-ir/godarai-postman-collections/issues) نام کامل مورد آزمون، `target`، کد وضعیت، شناسه request یا trace و `last_skip_reason` را بدون کلید دسترسی ثبت کنید.

## پرسش‌های پرتکرار

### آیا می‌توان همان تست‌ها را مستقیم روی OpenAI اجرا کرد؟

بله. فایل `OpenAI Official - Direct.postman_environment.json` را با `Import` وارد و انتخاب کنید و مقدار `openai_api_key` را بدهید. کالکشن همان است و فقط `target`، نشانی پایه، احراز هویت و روش تعیین مدل تغییر می‌کند.

### آیا `pnpm run check` همه ۶۵۱ تست API را اجرا می‌کند؟

خیر. این فرمان فایل‌ها و قرارداد داخلی کالکشن را اعتبارسنجی می‌کند. برای ارسال درخواست‌های واقعی باید گروه موردنظر را در Postman Collection Runner اجرا کنید.

### آیا باید همه ۲۱ مدل را از ابتدا نگاشت کنم؟

برای اجرای کامل کالکشن بله. برای تست یک گروه محدود می‌توانید فقط مدل‌های همان گروه را نگاشت کنید؛ تست‌های وابسته به مدل‌های دیگر با `BLOCKED` متوقف می‌شوند.
