# مدیریت واحدهای سازمانی

واحد سازمانی برای زمانی است که داخل یک فضای کاری، چند بخش بزرگ و نیمه‌مستقل دارید. این بخش‌ها می‌توانند تیم‌های خودشان را داشته باشند و مدیریت کاربران و تیم‌ها را مرتب‌تر کنند.

برای سازمان کوچک، معمولاً تیم کافی است. برای سازمانی که چند معاونت، محصول یا بخش عملیاتی دارد، واحد سازمانی کمک می‌کند ساختار دسترسی قابل فهم‌تر بماند.

## چه زمانی واحد سازمانی بسازیم؟

واحد سازمانی زمانی مفید است که یکی از این مرزها واقعی باشد:

- بخش سازمانی بزرگ‌تر از تیم
- مدیر یا مسئولیت جدا
- چند تیم زیرمجموعه یک بخش
- نیاز به گزارش و مدیریت در سطح بخش
- رشد آینده که تیم‌های بیشتری را زیر یک مرز مشترک قرار می‌دهد

مثال:

| واحد سازمانی | تیم‌های نمونه |
| --- | --- |
| عملیات | پشتیبانی، پرداخت، مانیتورینگ |
| محصول | موبایل، وب، تجربه مشتری |
| داده | پژوهش مدل، تحلیل کیفیت، جست‌وجو |

:::tip
اگر فقط دو تیم کوچک دارید، فعلاً واحد سازمانی نسازید. ساختار ساده‌تر معمولاً قابل فهم‌تر است و بعداً می‌توانید با رشد سازمان واحد سازمانی اضافه کنید.
:::

## ساخت واحد سازمانی

1. بخش «واحدهای سازمانی» را باز کنید.
2. یک واحد سازمانی جدید بسازید.
3. در «شناسه فنی»، مقدار کوتاه و پایدار وارد کنید؛ مثل `operations`.
4. در «نام نمایشی»، نام خوانا بنویسید؛ مثل «عملیات».
5. بعد از ساخت، تیم‌های مرتبط را به این واحد سازمانی وصل کنید.

## عضویت در واحد سازمانی

عضویت واحد سازمانی مشخص می‌کند یک کاربر در کدام بخش سازمانی نقش دارد. این عضویت جایگزین عضویت تیمی نیست؛ معمولاً واحد سازمانی برای مرز بزرگ‌تر و تیم برای کار روزمره استفاده می‌شود.

برای مثال، مدیر عملیات می‌تواند در واحد سازمانی «عملیات» نقش مدیریتی داشته باشد، اما اعضای تیم پشتیبانی فقط عضو تیم `support-prod` باشند.

## رابطه واحد سازمانی و تیم

هر تیم می‌تواند مستقیماً زیر فضای کاری باشد یا به یک واحد سازمانی وصل شود. اگر تیم‌ها را زیر واحد سازمانی درست بگذارید:

- پیدا کردن مالک تیم ساده‌تر می‌شود.
- گزارش‌ها برای بخش‌های بزرگ‌تر خواناتر می‌شوند.
- تفویض مدیریت در سازمان‌های بزرگ‌تر روشن‌تر می‌شود.

## خطاهای رایج

### ساخت واحد سازمانی برای هر تیم

اگر هر واحد فقط یک تیم دارد و مرز مدیریتی جدا ایجاد نمی‌کند، ساخت آن احتمالاً اضافه‌کاری است.

### استفاده از واحد سازمانی به‌جای تیم

واحد سازمانی برای مرز بزرگ‌تر است. برای توکن سرویس، اعضای روزمره و نوع محیط، تیم مناسب‌تر است.

### نام‌گذاری مبهم

شناسه‌هایی مثل `unit1` یا `main` بعداً در گزارش‌ها و دسترسی‌ها کمک نمی‌کنند. نام‌هایی مثل `operations`، `product` یا `data` خواناتر هستند.

## پرسش‌های پرتکرار

### آیا واحد سازمانی اجباری است؟

خیر. اگر ساختار شما ساده است، تیم‌ها را مستقیم زیر فضای کاری نگه دارید.

### آیا کاربر باید هم عضو واحد سازمانی باشد هم عضو تیم؟

برای کار روزمره، عضویت تیمی معمولاً مهم‌تر است. عضویت واحد سازمانی زمانی ارزش دارد که مدیریت یا گزارش در سطح بخش بزرگ‌تر دارید.

### آیا واحد سازمانی روی VAT اثر دارد؟

کاربر مجازی می‌تواند در محدوده واحد سازمانی و تیم قرار بگیرد، اما برای صدور VAT در مسیر فعلی، محدوده تیمی نقش کلیدی دارد.
