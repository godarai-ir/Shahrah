# قوانین محدودیت بودجه در گدارAI

قوانین محدودیت بودجه به شما کمک می‌کنند برای مصرف مالی مدل‌ها سقف مشخص داشته باشید. این سقف می‌تواند روزانه، هفتگی یا ماهانه باشد و روی کل فضای کاری، کاربر، تیم، واحد سازمانی، اکانت مجازی، مدل یا فراداده اعمال شود.

این صفحه توضیح می‌دهد محدودیت بودجه چه تفاوتی با کیف پول و محدودسازی نرخ دارد، چه فیلدهایی در UI می‌بینید و هنگام عبور از سقف چه اتفاقی برای درخواست می‌افتد.

:::info
کیف پول نشان می‌دهد فضای کاری شما پشتوانه مالی لازم را دارد یا نه. قانون بودجه یک سیاست عملیاتی است که پیش از رسیدن مصرف به وضعیت نامطلوب، سقف مالی دقیق‌تری برای بخش‌های مختلف محصول تعریف می‌کند.
:::

## چه زمانی قانون بودجه بسازیم؟

قانون بودجه برای این سناریوها مفید است:

- هر تیم یا واحد سازمانی باید سهم مشخصی از مصرف داشته باشد.
- یک مدل گران‌تر باید سقف جداگانه داشته باشد.
- هر پروژه یا مشتری باید بودجه مستقل داشته باشد.
- محیط‌های آزمایشی نباید هزینه محیط عملیاتی را تحت تأثیر قرار دهند.
- می‌خواهید قبل از عبور از آستانه‌های مهم، هشدار بودجه دریافت کنید.

محدودیت بودجه یعنی مصرف فقط قابل مشاهده نیست؛ قابل کنترل هم هست.

## تفاوت با محدودسازی نرخ

محدودسازی نرخ و محدودیت بودجه مکمل هم هستند:

| قابلیت | چه چیزی را کنترل می‌کند؟ | مثال |
| --- | --- | --- |
| قوانین محدودسازی نرخ | سرعت مصرف در بازه کوتاه | حداکثر ۶۰۰ درخواست در دقیقه برای پشتیبانی |
| قوانین محدودیت بودجه | سقف مالی در بازه بلندتر | حداکثر ۵۰ میلیون ریال در ماه برای یک تیم |

در عمل، محدودسازی نرخ جلوی جهش ناگهانی را می‌گیرد و محدودیت بودجه جلوی رشد تدریجی هزینه را.

## اجزای اصلی قانون بودجه

در UI گدارAI، قانون بودجه با عنوان «قوانین محدودیت بودجه» نمایش داده می‌شود. فیلدهای مهم آن این‌ها هستند:

| فیلد | توضیح |
| --- | --- |
| `شناسه فنی` | شناسه پایدار قانون برای گزارش‌ها و عیب‌یابی. |
| `نام نمایشی` | نامی که در UI و گزارش‌ها خوانده می‌شود. |
| `سقف بودجه (ریال)` | بیشترین هزینه مجاز در دوره انتخاب‌شده. |
| `واحد بودجه` | روزانه، هفتگی یا ماهانه. |
| `اعمال بودجه به‌ازای` | مشخص می‌کند بودجه مشترک است یا برای هر کاربر، تیم، مدل یا مقدار فراداده جدا حساب می‌شود. |
| `آستانه‌های هشدار (%)` | درصدهایی که با رسیدن مصرف به آن‌ها هشدار ارسال می‌شود. |
| `کانال اعلان` | مسیر دریافت هشدار، اگر در محیط شما فعال باشد. |
| `مسدودسازی بعد از عبور از بودجه` | تعیین می‌کند بعد از عبور از سقف، درخواست متوقف شود یا فقط ثبت و هشدار داده شود. |

:::tip
برای بودجه‌های مهم، آستانه‌های ۷۵، ۹۰ و ۱۰۰ درصد معمولاً نقطه شروع خوبی هستند: اولی برای واکنش زودهنگام، دومی برای هشدار جدی و سومی برای کنترل نهایی.
:::

## اعمال بودجه به‌ازای چه چیزی؟

فیلد «اعمال بودجه به‌ازای» تعیین می‌کند یک سقف بودجه چطور بین مصرف‌کننده‌ها تقسیم شود.

| گزینه | نتیجه |
| --- | --- |
| اشتراکی برای همه ترافیک | همه درخواست‌های منطبق از یک بودجه مشترک مصرف می‌کنند. |
| به‌ازای کل فضای کاری | بودجه در سطح کل فضای کاری اعمال می‌شود. |
| به‌ازای هر کاربر | هر کاربر سقف مستقل خودش را دارد. |
| به‌ازای هر تیم | هر تیم جداگانه محاسبه می‌شود. |
| به‌ازای هر واحد سازمانی | هر واحد سازمانی سهم مستقل دارد. |
| به‌ازای هر مدل | هزینه هر مدل جدا حساب می‌شود. |
| به‌ازای هر اکانت مجازی | هر اکانت مجازی بودجه مستقل دارد. |
| به‌ازای `metadata.project_id` | هر پروژه بر اساس فراداده بودجه جدا دارد. |

اگر چند محصول از یک توکن مشترک استفاده می‌کنند، گزینه‌های مبتنی بر فراداده مثل `project_id` یا `cost_center` معمولاً گزارش‌پذیری بهتری می‌دهند.

## نمونه قانون مفهومی

نمونه زیر یک قانون روزانه برای مرکز پشتیبانی را نشان می‌دهد. عددها نمونه‌اند و باید با سیاست مالی فضای کاری شما تنظیم شوند.

```json
{
  "rule_id": "support-daily-budget",
  "name": "بودجه روزانه پشتیبانی",
  "enabled": true,
  "limit_to": 50000000,
  "unit": "cost_per_day",
  "budget_applies_per": "metadata.project_id",
  "metadata_key": "project_id",
  "block_on_exceed": true,
  "alert_thresholds": [75, 90, 100]
}
```

نمونه بعدی برای یک مدل گران‌تر است:

```json
{
  "rule_id": "premium-model-monthly-budget",
  "name": "بودجه ماهانه مدل‌های پریمیوم",
  "enabled": true,
  "limit_to": 300000000,
  "unit": "cost_per_month",
  "budget_applies_per": "model",
  "block_on_exceed": true,
  "alert_thresholds": [80, 95]
}
```

## وقتی بودجه رد می‌شود چه اتفاقی می‌افتد؟

اگر قانون مؤثر اجازه ادامه ندهد، گدارAI درخواست را پیش از ارسال به ارائه‌دهنده مدل متوقف می‌کند. در این وضعیت معمولاً پاسخ `402 Payment Required` با کد خطای `budget_exceeded` برمی‌گردد.

این رفتار چند اثر مهم دارد:

- هزینه تازه‌ای برای درخواست ردشده ایجاد نمی‌شود.
- دلیل رد شدن در گزارش رخدادها قابل بررسی است.
- کیف پول همچنان لایه نهایی محافظت مالی باقی می‌ماند.
- کاربر یا کلاینت می‌تواند رفتار مناسب مثل نمایش پیام، کاهش مدل یا تلاش در دوره بعد را اجرا کند.

:::warning
در برخی مسیرها هزینه ابتدا برآورد می‌شود و بعد از پاسخ ارائه‌دهنده مدل دقیق‌تر ثبت می‌شود. برای مسیرهای تصویری، صوتی یا مدل‌های با قیمت‌گذاری خاص، گزارش هزینه را با داده واقعی فضای کاری خودتان بررسی کنید.
:::

## رابطه بودجه با کیف پول

کیف پول و قانون بودجه دو لایه متفاوت‌اند:

| لایه | نقش |
| --- | --- |
| کیف پول | پشتوانه مالی کل فضای کاری. اگر موجودی کافی نباشد، درخواست متوقف می‌شود. |
| قانون بودجه | سیاست مصرف برای کاربر، تیم، مدل، پروژه یا بخش‌های دیگر. |

ممکن است یک تیم هنوز از بودجه خودش عبور نکرده باشد، اما کیف پول فضای کاری موجودی کافی نداشته باشد. همچنین ممکن است کیف پول موجودی داشته باشد، اما قانون بودجه همان تیم اجازه ادامه ندهد.

## الگوهای پیشنهادی

### بودجه روزانه برای هر تیم

برای تیم‌هایی که مصرف روزانه قابل توجه دارند، بودجه روزانه تعریف کنید تا افزایش ناگهانی هزینه همان روز دیده و کنترل شود.

### بودجه ماهانه برای مدل‌های گران‌تر

مدل‌هایی که هزینه بیشتری دارند بهتر است سقف جدا داشته باشند. این کار باعث می‌شود یک مدل خاص بودجه عمومی را سریع مصرف نکند.

### بودجه پروژه‌ای با فراداده

اگر محصول شما `metadata.project_id` یا `metadata.cost_center` می‌فرستد، بودجه را بر همین اساس جدا کنید. این الگو برای محصولات چندمشتری یا چندپروژه‌ای بسیار کاربردی است.

### شروع با حالت هشدار

اگر هنوز درباره عدد سقف مطمئن نیستید، ابتدا هشدارها را فعال کنید و بعد از چند روز مشاهده، مسدودسازی بعد از عبور از بودجه را روشن کنید.

## عیب‌یابی سریع

| وضعیت | علت‌های رایج | چه کار کنید؟ |
| --- | --- | --- |
| بودجه زودتر از انتظار تمام می‌شود | قانون روی محدوده خیلی عمومی اعمال شده یا مدل گران‌تری استفاده می‌شود. | گزارش هزینه را به تفکیک مدل، تیم و فراداده بررسی کنید. |
| قانون اثر نمی‌گذارد | وضعیت قانون غیرفعال است یا شرط‌ها با درخواست منطبق نیستند. | شناسه قانون و فراداده درخواست را در گزارش رخدادها بررسی کنید. |
| هشدارها دیر می‌رسند | آستانه‌ها خیلی بالا هستند یا کانال اعلان درست تنظیم نشده است. | آستانه‌های پایین‌تر اضافه کنید و کانال اعلان را آزمایش کنید. |
| درخواست با وجود بودجه کافی رد می‌شود | کیف پول موجودی کافی ندارد یا قانون دیگری محدودکننده‌تر است. | وضعیت کیف پول و قوانین منطبق را کنار هم بررسی کنید. |

## جمع‌بندی

قوانین محدودیت بودجه در گدارAI لایه‌ای برای کنترل مالی عملیاتی هستند. با سقف ریالی روشن، دوره زمانی مناسب، تفکیک درست بین کاربرها یا پروژه‌ها و هشدارهای به‌موقع، می‌توانید هزینه را پیش از تبدیل شدن به بحران مدیریت کنید.
