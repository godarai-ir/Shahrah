# PII پایه

گاردریل `basic_pii` چند الگوی رایج داده شخصی را در متن پیدا می‌کند. از این نوع وقتی استفاده کنید که می‌خواهید ایمیل، شماره موبایل ایران یا شماره‌های رایج قبل از رسیدن به مدل، یا قبل از نمایش پاسخ، کنترل شوند.

این گاردریل تشخیص معنایی انجام نمی‌دهد. یعنی نام اشخاص، آدرس، کدهای داخلی سازمان یا داده‌هایی که فقط از زمینه جمله قابل تشخیص‌اند، با این نوع پوشش داده نمی‌شوند.

## چه زمانی استفاده کنید؟

این گاردریل برای سناریوهای زیر مناسب است:

- ماسک‌کردن ایمیل در ورودی کاربر.
- ماسک‌کردن شماره موبایل ایران.
- جلوگیری از عبور عددهای ۱۰ رقمی که ممکن است شناسه حساس باشند.
- ماسک‌کردن شماره‌های ۱۶ رقمی با فاصله یا خط تیره اختیاری.

برای داده‌های اختصاصی سازمان، این گاردریل را کنار [Regex](/guardrails-regex) استفاده کنید.

## رفتار اجرایی

این نوع از هر دو «نوع اقدام» پشتیبانی می‌کند:

| نوع اقدام | مقدار API | رفتار |
| --- | --- | --- |
| اعتبارسنجی | `validate` | اگر داده شخصی پایه پیدا شود، نتیجه بررسی ناموفق می‌شود. |
| اصلاح محتوا | `mutate` | تطابق‌ها با «متن جایگزین» جایگزین می‌شوند. |

در حالت «اصلاح محتوا»، متن اصلاح‌شده به ارائه‌دهنده یا مصرف‌کننده پاسخ می‌رسد. در حالت «اعتبارسنجی»، توقف یا ادامه مسیر به «شیوه اعمال» بستگی دارد.

## الگوهای داخلی

این نوع الگوهای زیر را بررسی می‌کند:

- ایمیل.
- شماره موبایل ایران، مثل `09123456789` یا `+989123456789`.
- عدد ۱۰ رقمی.
- شماره ۱۶ رقمی با فاصله یا خط تیره اختیاری.

## تنظیمات

| عنوان | مقدار API | توضیح |
| --- | --- | --- |
| متن جایگزین | `redaction_text` | فقط برای «اصلاح محتوا» استفاده می‌شود. اگر از API مقدار ندهید، موتور از `[REDACTED]` استفاده می‌کند. |

مقدار پیشنهادی «متن جایگزین» برابر `[***]` است.

## نمونه تعریف

```json
{
  "slug": "mask-basic-pii",
  "name": "Mask basic PII",
  "type": "basic_pii",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "redaction_text": "[***]"
  }
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/mask-basic-pii"]}
```

اگر متن کاربر این باشد:

```text
ایمیل من user@example.com است.
```

در حالت «اصلاح محتوا»، متن ارسالی به مدل به این شکل تغییر می‌کند:

```text
ایمیل من [***] است.
```

## گاردریل‌های آماده

گدارAI این شناسه‌های فنی آماده را برای همین رفتار دارد:

```text
guardrails/basic-pii
guardrails/pii-redaction
guardrails/pii-detection
```

هر سه شناسه فنی به گاردریل داخلی `basic_pii` می‌رسند و مقدارهای پیدا‌شده را با `[REDACTED]` جایگزین می‌کنند.

## چه زمانی «اصلاح محتوا» بهتر است؟

اگر وجود داده شخصی ناخواسته است، اما کار اصلی بدون آن داده هم ادامه پیدا می‌کند، «اصلاح محتوا» معمولاً تجربه بهتری می‌دهد. اگر خودِ وجود آن داده تخطی جدی از سیاست شماست، «اعتبارسنجی» همراه با «عدم عبور و لاگ» مناسب‌تر است.

## محدودیت‌ها

- این گاردریل فقط چند الگوی پایه را می‌شناسد.
- عدد ۱۰ رقمی ممکن است همیشه داده شخصی نباشد.
- نام افراد، آدرس، شناسه‌های داخلی و داده‌های مبهم معنایی پوشش داده نمی‌شوند.
- اگر داده پیش از اجرای گاردریل در جایی ثبت شده باشد، اصلاح بعدی آن ثبت قبلی را پاک نمی‌کند.

## گام بعدی

- برای داده‌های سازمانی، [Regex](/guardrails-regex) را کنار PII پایه استفاده کنید.
- برای توکن و کلید خصوصی، [تشخیص Secret](/guardrails-secrets-detection) را ببینید.
