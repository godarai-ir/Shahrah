# PII پایه و Redaction

`basic_pii` برای تشخیص یا ماسک‌کردن چند الگوی رایج داده شخصی در متن استفاده می‌شود. این گاردریل deterministic است و بر اساس patternهای داخلی کار می‌کند، نه تشخیص معنایی یا مدل جداگانه.

## چه زمانی استفاده کنیم؟

از این گاردریل وقتی استفاده کنید که می‌خواهید داده‌های عمومی و رایج قبل از ارسال به مدل یا قبل از تحویل پاسخ کنترل شوند.

نمونه use caseها:

- ماسک‌کردن ایمیل در prompt کاربر
- ماسک‌کردن شماره موبایل ایران
- جلوگیری از عبور عددهای ۱۰ رقمی که ممکن است شناسه حساس باشند
- ماسک‌کردن شماره کارت‌های ۱۶ رقمی با فاصله یا خط تیره اختیاری

## رفتار اجرایی

این نوع از هر دو عملیات پشتیبانی می‌کند:

| operation | رفتار |
| --- | --- |
| `validate` | اگر PII پایه match شود، check ناموفق می‌شود. |
| `mutate` | matchها با `redaction_text` جایگزین می‌شوند. |

در حالت `mutate`، متن تغییر یافته به provider یا مصرف‌کننده پاسخ داده می‌شود. در حالت `validate`، نتیجه توقف یا فقط ثبت شدن به `enforcement` بستگی دارد.

## الگوهای داخلی

در implementation فعلی، این patternها بررسی می‌شوند:

- ایمیل
- شماره موبایل ایران با الگوهای شبیه `09123456789` یا `+989123456789`
- عدد ۱۰ رقمی
- شماره ۱۶ رقمی با فاصله یا خط تیره اختیاری

این فهرست پایه است. نام اشخاص، آدرس، کدهای داخلی سازمانی یا PIIهای domain-specific را پوشش نمی‌دهد. برای آن‌ها از [Regex](/guardrails-regex) استفاده کنید.

## تنظیمات

| فیلد | نوع | اجباری | توضیح |
| --- | --- | --- | --- |
| `redaction_text` | `string` | خیر | متن جایگزین در حالت `mutate`. مقدار پیش‌فرض `[REDACTED]` است. |

## نمونه تعریف

```json
{
  "slug": "mask-basic-pii",
  "name": "Mask basic PII",
  "type": "basic_pii",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "redaction_text": "[PII]"
  }
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/mask-basic-pii"]}
```

اگر متن کاربر این باشد:

```text
ایمیل من user@example.com است.
```

متن ارسالی به مدل در حالت `mutate` به این شکل تغییر می‌کند:

```text
ایمیل من [PII] است.
```

## selectorهای آماده

موتور پیش‌فرض این selectorها را برای همین رفتار دارد:

```text
guardrails/basic-pii
guardrails/pii-redaction
guardrails/pii-detection
```

هر سه selector به evaluator داخلی `basic_pii` می‌رسند و در حالت پیش‌فرض matchها را با `[REDACTED]` جایگزین می‌کنند.

## چه زمانی redaction بهتر از deny است؟

اگر حضور داده حساس ناخواسته است اما کار اصلی بدون آن داده هم ادامه پیدا می‌کند، `operation: "mutate"` معمولا تجربه بهتری می‌دهد. اگر حضور آن داده خودش نقض policy است، `operation: "validate"` با `enforcement: "enforce"` مناسب‌تر است.

## محدودیت‌ها

- این گاردریل فقط چند pattern پایه را می‌شناسد.
- عدد ۱۰ رقمی ممکن است false positive بسازد.
- نام افراد، آدرس، شناسه‌های داخلی و داده‌های مبهم معنایی پوشش داده نمی‌شوند.
- اگر داده پیش از اجرای guardrail در جایی log شده باشد، redaction بعدی آن log قبلی را پاک نمی‌کند.

برای داده‌های سازمانی و الگوهای اختصاصی، [Regex Guardrail](/guardrails-regex) را کنار این گاردریل استفاده کنید.
