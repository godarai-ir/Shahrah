# عبارت‌های مسدود (Keyword Blocklist)

`keyword_blocklist` ساده‌ترین نوع گاردریل برای متوقف‌کردن عبارت‌های مشخص است. این گاردریل متن ورودی یا خروجی مدل را با «عبارت‌های مسدود» مقایسه می‌کند و اگر یکی از آن‌ها پیدا شود، نتیجه بررسی را ناموفق می‌کند.

این گاردریل فقط از «اعتبارسنجی» (`operation: "validate"`) پشتیبانی می‌کند. اگر می‌خواهید متن را تغییر دهید یا مقدار حساس را جایگزین کنید، از [Regex](/guardrails-regex)، [جایگزینی با Regex](/guardrails-regex-replace) یا [PII پایه](/guardrails-pii-redaction) استفاده کنید.

## چه زمانی استفاده کنیم؟

از این گاردریل وقتی استفاده کنید که سیاست شما با چند عبارت ثابت و قطعی قابل بیان است؛ برای نمونه، عبارت‌های شناخته‌شده تزریق پرامپت، دستورهای عملیاتی پرریسک یا عبارت‌هایی که در محصول شما نباید به مدل برسند.

نمونه‌های مناسب:

- جلوگیری از تزریق پرامپت ساده مثل `ignore previous instructions`
- جلوگیری از دستورهای پرریسک مثل `drop table`
- مسدودکردن نام پروژه، عبارت داخلی یا کد عملیاتی مشخص
- ثبت آزمایشی تخطی‌ها با «عبور همراه با نشانه‌گذاری» پیش از فعال‌کردن توقف مسیر

اگر لازم است الگو، فاصله‌گذاری، قالب شناسه یا چند شکل نوشتاری متفاوت را تشخیص دهید، [Regex](/guardrails-regex) انتخاب دقیق‌تری است.

## رفتار اجرایی

در زمان اجرا:

- گدارAI متن ورودی یا خروجی را به حروف کوچک تبدیل می‌کند.
- هر مقدار داخل `terms` با جست‌وجوی زیررشته بررسی می‌شود.
- اگر عبارت پیدا شود، مقدار `reason` برابر `Keyword blocklist matched` ثبت می‌شود.
- با «عبور همراه با نشانه‌گذاری»، نتیجه با وضعیت `flagged` ثبت می‌شود و مسیر ادامه پیدا می‌کند.
- با «عدم عبور و لاگ» یا «عدم عبور - بدون لاگ»، درخواست یا پاسخ متوقف می‌شود.

جست‌وجو حساس به بزرگی و کوچکی حروف انگلیسی نیست، اما معنایی نیست و فقط وجود همان زیررشته را بررسی می‌کند.

## تنظیمات

برای این نوع فقط یک تنظیم لازم است:

| عنوان | مقدار API | توضیح |
| --- | --- | --- |
| عبارت‌های مسدود | `terms` | هر خط یک عبارت است. دست‌کم یک عبارت لازم است. |

عبارت‌های خیلی کوتاه می‌توانند باعث تطابق اشتباه شوند؛ تا جای ممکن عبارت کامل و مشخص وارد کنید.

## نمونه تعریف

نمونه زیر عبارت‌های رایج تزریق پرامپت و یک دستور پرریسک را متوقف می‌کند:

```json
{
  "slug": "no-injection",
  "name": "No simple prompt injection",
  "description": "Block known prompt injection phrases.",
  "type": "keyword_blocklist",
  "operation": "validate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "terms": [
      "ignore previous instructions",
      "jailbreak",
      "drop table"
    ]
  }
}
```

پس از ذخیره، شناسه فنی این گاردریل `guardrails/no-injection` است.

## نمونه استفاده روی ورودی

شناسه فنی گاردریل را در سرآیند `x-godarai-guardrails` بفرستید:

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/no-injection"]}
```

برای بررسی فقط آخرین پیام کاربر، سرآیند محدوده اجرا را هم اضافه کنید:

```text
x-godarai-guardrails-scope: last
```

اگر متن آخرین پیام کاربر شامل `ignore previous instructions` باشد و «شیوه اعمال» برابر «عدم عبور و لاگ» باشد، درخواست پیش از ارسال به ارائه‌دهنده متوقف می‌شود.

## نمونه استفاده روی خروجی

برای کنترل پاسخ مدل، شناسه فنی را در `llm_output_guardrails` قرار دهید:

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/no-injection"]}
```

گاردریل خروجی فقط برای پاسخ غیرجریانی پشتیبانی می‌شود. اگر درخواست شما `stream: true` دارد، گدارAI ترکیب آن با `llm_output_guardrails` را با خطای `400` رد می‌کند.

## بررسی نتیجه

اگر تطابق مسیر را متوقف کند، پاسخ خطا شامل `guardrail_checks` است:

```json
{
  "error": {
    "message": "Request blocked by GodarAI guardrail",
    "type": "guardrail_checks_failed",
    "code": "guardrail_blocked"
  },
  "guardrail_checks": {
    "llm_input_guardrails": [
      {
        "selector": "guardrails/no-injection",
        "status": "blocked",
        "operation": "validate",
        "enforcement": "enforce",
        "reason": "Keyword blocklist matched",
        "latency_ms": 0
      }
    ]
  }
}
```

در حالت «عبور همراه با نشانه‌گذاری»، وضعیت به‌جای `blocked` برابر `flagged` می‌شود و مسیر متوقف نمی‌شود.

## گاردریل آماده

موتور پیش‌فرض گدارAI این شناسه فنی آماده را هم دارد:

```text
guardrails/keyword-blocklist
```

این گاردریل آماده عبارت‌های زیر را بررسی می‌کند:

- `ignore previous instructions`
- `jailbreak`
- `rm -rf`
- `drop table`

برای محیط عملیاتی، بهتر است گاردریل اختصاصی فضای کاری خودتان را بسازید تا فهرست عبارت‌ها، هدف و مالکیت آن برای تیم قابل بازبینی باشد.

## رفع مشکل‌های رایج

### عبارت ممنوع پیدا نمی‌شود

این گاردریل فقط زیررشته دقیق را بررسی می‌کند. فاصله‌گذاری متفاوت، غلط املایی، نیم‌فاصله، بازنویسی عبارت یا ترجمه ممکن است تطابق ندهد. برای حالت‌های پیچیده‌تر از [Regex](/guardrails-regex) استفاده کنید.

### عبارت‌های بی‌خطر هم مسدود می‌شوند

عبارت‌های کوتاه یا عمومی می‌توانند تطابق اشتباه بسازند. مقدارهای `terms` را طولانی‌تر و زمینه‌مندتر کنید، یا ابتدا با «عبور همراه با نشانه‌گذاری» اثر آن‌ها را در گزارش رخدادها بررسی کنید.

### درخواست متوقف نمی‌شود

«شیوه اعمال» را بررسی کنید. اگر برابر «عبور همراه با نشانه‌گذاری» باشد، تخطی فقط با وضعیت `flagged` ثبت می‌شود. برای توقف مسیر، از «عدم عبور و لاگ» استفاده کنید.

## محدودیت‌ها

- این گاردریل معنایی نیست و فقط زیررشته را بررسی می‌کند.
- عبارت‌های کوتاه می‌توانند تطابق اشتباه بسازند.
- فاصله‌گذاری، املای متفاوت یا بازنویسی عبارت ممکن است تشخیص داده نشود.
- این گاردریل متن را تغییر نمی‌دهد و فقط برای اعتبارسنجی استفاده می‌شود.

## گام بعدی

- برای الگوهای دقیق‌تر، [Regex](/guardrails-regex) را ببینید.
- برای ماسک‌کردن داده شخصی، [PII پایه](/guardrails-pii-redaction) را بخوانید.
- برای شناخت محدوده اجرا، [قابلیت‌ها و محدوده پشتیبانی گاردریل‌ها](/guardrails-capabilities) را مرور کنید.
