# تشخیص وجود کد

`contains_code` وجود محتوای شبیه کد را با code fence و markerهای متنی داخلی تشخیص می‌دهد. می‌توانید وجود کد را الزامی یا ممنوع کنید.

## چه زمانی استفاده کنیم؟

- الزام پاسخ مدل به داشتن نمونه کد
- جلوگیری از تولید کد در یک جریان فقط متنی
- محدودکردن تشخیص به چند زبان مشخص

## رفتار اجرایی

این نوع فقط از `operation: "validate"` پشتیبانی می‌کند.

| mode | شرط قبولی |
| --- | --- |
| `must_contain` | متن باید کد تشخیص‌پذیر داشته باشد. مقدار پیش‌فرض است. |
| `must_not_contain` | متن نباید کد تشخیص‌پذیر داشته باشد. |

موتور ابتدا fence سه‌تایی backtick را بررسی می‌کند. سپس برای زبان‌های شناخته‌شده markerهایی مثل `select ... from`، `def`، `import`، `function`، `const`، `func`، `package`، `curl` و shebang را جست‌وجو می‌کند.

## تنظیمات

| فیلد | نوع | اجباری | توضیح |
| --- | --- | --- | --- |
| `languages` | `string[]` | خیر | زبان‌های مورد بررسی. بدون این فیلد، `sql`، `python`، `typescript`، `javascript`، `go` و `shell` بررسی می‌شوند. |
| `mode` | `must_contain \| must_not_contain` | خیر | policy مورد نظر؛ پیش‌فرض `must_contain`. |
| `must_contain` | `boolean` | خیر | فرم قدیمی‌تر همان policy. اگر همراه `mode` ارسال شود، این boolean اولویت دارد. |

## نمونه تعریف برای منع SQL

```json
{
  "slug": "no-sql-output",
  "name": "No SQL in output",
  "type": "contains_code",
  "operation": "validate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "languages": ["sql"],
    "mode": "must_not_contain"
  }
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/no-sql-output"]}
```

## محدودیت‌ها

- تشخیص heuristic است و parser یا compiler زبان نیست.
- markerهای داخل متن عادی می‌توانند false positive و کد با syntax متفاوت می‌تواند false negative بسازد.
- برای زبان ناشناخته، فقط fence دارای label همان زبان قابل تشخیص است.
- هر متن انتخاب‌شده جداگانه باید policy را پاس کند.
- این نوع فقط tenant-level است و output streaming را پشتیبانی نمی‌کند.
