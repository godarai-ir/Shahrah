# نرخ‌نامه کردیتی

واحد مصرف گدارAI **کردیت** است. کردیت واحد پایداری است که با نوسان نرخ ارز تغییر نمی‌کند: نرخ هر مدل بر حسب کردیت مستقیم از قیمت رسمی ارائه‌دهنده ساخته می‌شود و فقط قیمت خرید کردیت به تومان می‌تواند تغییر کند.

:::info صورت‌حساب کردیتی
همه فضاهای کاری بر حسب کردیت محاسبه می‌شوند: مصرف هر درخواست از موجودی کردیت کم می‌شود و قوانین بودجه هم بر حسب کردیت‌اند. کیف پول ریالی و فاکتورهای ریالی دیگر استفاده نمی‌شوند.
:::

## واحد کردیت

- مبلغ کردیت همیشه با دو رقم اعشار نمایش داده می‌شود، مثل `4.50`.
- نسبت ورودی به خروجی، تخفیف خواندن از کش، هزینه نوشتن در کش و هزینه ابزارها همان نسبت‌های ارائه‌دهنده است.
- کردیت هر درخواست یک بار و روی جمع کل همان درخواست به بالا و تا `0.01` کردیت گرد می‌شود.
- پاسخ‌هایی که از کش گدارAI برگردانده می‌شوند، برای خود پاسخ کردیتی مصرف نمی‌کنند.

## خواندن نرخ‌نامه

نرخ‌نامه از مسیر عمومی زیر در دسترس است و به کلید دسترسی نیاز ندارد:

```bash
curl https://YOUR_WORKSPACE.godarai.ir/v1/rate-card
```

نمونه پاسخ:

```json
{
  "object": "rate_card",
  "version": "rc-1",
  "effective_from": "2026-10-12T00:00:00Z",
  "unit": "credit",
  "models": [
    {
      "model": "anthropic/claude-sonnet-5",
      "provider": "anthropic",
      "rates": [
        { "dimension": "input_tokens", "per": "1k_tokens", "credits": "1.00" },
        { "dimension": "output_tokens", "per": "1k_tokens", "credits": "5.00" },
        { "dimension": "cache_read_input_tokens", "per": "1k_tokens", "credits": "0.10" },
        { "dimension": "web_search_requests", "per": "request", "credits": "5.00" }
      ],
      "typical_message_credits": "4.50"
    }
  ]
}
```

| فیلد | توضیح |
| --- | --- |
| `version` | نسخه نرخ‌نامه. هر تغییر در ضریب مدل‌ها نسخه تازه‌ای می‌سازد و در تغییرات قیمت اعلام می‌شود. |
| `rates[].per` | مبنای نرخ: `1k_tokens` برای هر هزار توکن، `1k_characters` برای هر هزار نویسه، و برای واحدهای دیگر نام همان واحد، مثل `request` یا `image`. |
| `rates[].credits` | نرخ بر حسب کردیت. نرخ‌های خیلی کوچک تا شش رقم اعشار برگردانده می‌شوند. |
| `rates[].condition` | شرط اعمال نرخ، مثل سطح سرویس یا بازه طول ورودی، اگر نرخ شرطی باشد. |
| `typical_message_credits` | کردیت تقریبی یک پیام معمولی با ۲۰۰۰ توکن ورودی و ۵۰۰ توکن خروجی. برای نمایش «مصرف تقریبی هر پیام» کنار انتخابگر مدل مناسب است. |

پاسخ با سرآیند `ETag` و `Cache-Control: public, max-age=300` برمی‌گردد. اگر مقدار `ETag` قبلی را در سرآیند `If-None-Match` بفرستید و نرخ‌نامه تغییری نکرده باشد، پاسخ `304 Not Modified` بدون بدنه دریافت می‌کنید.

## کردیت مصرفی هر پاسخ

وقتی محاسبه کردیت برای فضای کاری فعال باشد، گدارAI کردیت مصرفی را کنار سرآیندهای هزینه برمی‌گرداند:

| محل | مقدار |
| --- | --- |
| پاسخ‌های غیر stream | سرآیند `x-godarai-credits-used`، مثل `4.50` |
| پاسخ‌های stream | فیلد `credits` در رویداد `godarai.telemetry`، وقتی سرآیند `x-godarai-include-stream-telemetry: true` ارسال شده باشد |

```text
event: godarai.telemetry
data: {"object":"godarai.telemetry","usage":{"prompt_tokens":2000,"completion_tokens":500,"total_tokens":2500},"cost_usd":0.009,"cost_irr":2430,"credits":"4.50"}
```

سرآیندهای ریالی فعلی تا پایان دوره انتقال حفظ می‌شوند. برای گزارش مالی نهایی همچنان به گزارش‌ها و اسناد مالی فضای کاری تکیه کنید.

## تاریخچه‌ی تغییرات قیمت

هر تغییر در قیمت هر کردیت یا نرخ‌نامه‌ی مدل‌ها با تاریخ اعمالش ثبت می‌شود. این تاریخچه در صفحه‌ی «تغییرات قیمت و نرخ‌نامه» در سایت گدارAI و از این endpoint عمومی در دسترس است:

```bash
curl https://YOUR_WORKSPACE.godarai.ir/v1/pricing/changelog
```

| فیلد | توضیح |
| --- | --- |
| `credit_prices[].price_toman_per_credit` | قیمت هر کردیت به تومان |
| `credit_prices[].effective_from` | از این زمان بسته‌های کردیت با این قیمت فروخته می‌شوند |
| `credit_prices[].plan_effective_from` | پلن‌ها از اولین دوره‌ی بعد از این زمان با قیمت جدید تمدید می‌شوند |
| `rate_cards[].label` و `effective_from` | نسخه‌ی نرخ‌نامه و زمان اعمال آن؛ وضعیت `scheduled` یعنی هنوز در دوره‌ی اطلاع‌رسانی است |

قواعد اعمال تغییرات:

- کردیت‌هایی که قبلاً خریده‌اید هیچ‌وقت ارزش مصرفی‌شان کم نمی‌شود.
- قیمت بسته‌های کردیت از لحظه‌ی تأیید تغییر می‌کند و فقط روی خریدهای بعدی اثر دارد.
- افزایش قیمت پلن‌ها ۳۰ روز پیش از اعمال اعلام می‌شود و از دوره‌ی بعدی هر اشتراک اعمال می‌شود.
- افزایش نرخ یک مدل در نرخ‌نامه ۳۰ روز در وضعیت `scheduled` می‌ماند و بعد اعمال می‌شود؛ کاهش نرخ‌ها فوراً اعمال می‌شود.
