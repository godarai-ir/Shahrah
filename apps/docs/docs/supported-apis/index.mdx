# APIهای متنی و داده

این بخش به APIهایی می‌پردازد که متن، پیام، خروجی ساختاریافته یا داده قابل جست‌وجو تولید می‌کنند. اگر می‌خواهید گدارAI را در محصول خودتان به کار بگیرید، این دسته معمولاً همان جایی است که تصمیم می‌گیرید «کدام نقطه پایانی برای این کار درست است؟».

قاعده شروع ساده است:

| نیاز شما | API پیشنهادی | دلیل انتخاب |
| --- | --- | --- |
| تولید پاسخ متنی، چت، ابزارها و خروجی ساختاریافته | [Chat Completions](/supported-apis/chat-completions/overview) | رایج‌ترین مسیر سازگار با OpenAI برای بیشتر محصولات متنی است. |
| کار با قرارداد جدیدتر OpenAI برای تولید پاسخ | [Responses API](/supported-apis/responses-api) | وقتی تیم شما از ابتدا روی الگوی Responses طراحی می‌کند مناسب‌تر است. |
| سازگاری با قرارداد بومی Anthropic | [Messages API](/supported-apis/messages) | برای تیم‌هایی مهم است که به شکل پیام‌های Claude وابسته‌اند. |
| جست‌وجوی معنایی و RAG | [Embeddings](/supported-apis/embeddings) | متن را به بردار عددی تبدیل می‌کند تا بتوانید شباهت معنایی را بسنجید. |
| بهترکردن ترتیب نتایج بازیابی | [Rerank](/supported-apis/rerank) | پس از جست‌وجوی اولیه، نتایج مرتبط‌تر را بالاتر می‌آورد. |
| ساخت پایگاه دانش و پاسخ دارای ارجاع | [RAG مدیریت‌شده](/supported-apis/managed-rag) | بارگذاری، بازیابی، بازچینی و اعتبارسنجی ارجاع را در یک مسیر نسخه‌دار اجرا می‌کند. |
| بررسی ایمنی و سیاست محتوایی متن | [Moderation](/supported-apis/moderation) | پیش از نمایش یا پردازش متن، ریسک محتوایی را ارزیابی می‌کند. |
| پردازش انبوه و غیرتعاملی | [Batch API](/supported-apis/batch-api) | برای کارهای دسته‌ای و ناهم‌زمان طراحی می‌شود. |

## مسیر پیشنهادی مطالعه

اگر تازه با گدارAI شروع کرده‌اید، این ترتیب معمولاً کم‌ابهام‌ترین مسیر است:

1. [Chat Completions](/supported-apis/chat-completions/overview) را بخوانید و یک درخواست ساده بفرستید.
2. اگر خروجی باید JSON قابل اتکا باشد، [خروجی ساختاریافته](/supported-apis/chat-completions/structured-outputs) را اضافه کنید.
3. اگر مدل باید داده بیرونی بگیرد یا کاری در سیستم شما انجام دهد، [ابزارها](/supported-apis/chat-completions/tools) را بخوانید.
4. برای جست‌وجوی دانش، [Embeddings](/supported-apis/embeddings) و سپس [Rerank](/supported-apis/rerank) را ببینید.
5. برای کنترل ریسک محتوایی، [Moderation](/supported-apis/moderation) را در مسیر ورودی یا خروجی خود قرار دهید.

## سه اصل قبل از ارسال درخواست

- شناسه مدل را حدس نزنید؛ آن را از مدل‌های مجاز فضای کاری یا مدل مجازی بردارید.
- برای آزمایش انسانی از توکن دسترسی شخصی و برای سرویس‌های محیط عملیاتی از کلید دسترسی مجازی استفاده کنید.
- پس از هر اتصال جدید، نتیجه را در گزارش رخدادها، سنجه‌ها و مصرف توکن بررسی کنید تا رفتار، هزینه و خطاها قابل پیگیری باشد.

## پرسش‌های پرتکرار

### از کدام API شروع کنم؟

برای بیشتر محصولات متنی، `Chat Completions` نقطه شروع مناسب‌تری است. بعد از پایدارشدن درخواست ساده، می‌توانید ابزارها، خروجی ساختاریافته، حافظه نهان یا استدلال را به همان مسیر اضافه کنید.

### آیا همه APIهای این دسته در همه محیط‌ها فعال‌اند؟

خیر. فعال‌بودن هر API به تنظیمات فضای کاری، مدل‌های مجاز و ارائه‌دهنده‌های متصل بستگی دارد. در هر صفحه گفته می‌شود که چه چیزی باید در محیط شما فعال باشد.

### آیا APIهای متنی و داده جای گاردریل‌ها را می‌گیرند؟

خیر. `Moderation` یک API مدل برای ارزیابی محتواست. گاردریل‌ها لایه اعمال سیاست در گدارAI هستند و می‌توانند قبل یا بعد از فراخوانی مدل اجرا شوند.
