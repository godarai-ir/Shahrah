# Speech to Text

`Speech to Text` برای تبدیل فایل صوتی به متن استفاده می‌شود. این API با قرارداد رایج OpenAI Whisper سازگار است و از مسیر زیر در گدارAI در دسترس است:

```text
POST /v1/audio/transcriptions
```

درخواست باید با `multipart/form-data` ارسال شود. گدارAI مدل را اعتبارسنجی می‌کند، مسیر مناسب ارائه‌دهنده را پیدا می‌کند، مقدار `model` را برای ارائه‌دهنده بازنویسی می‌کند و فایل صوتی را بدون ثبت محتوای خام به provider می‌فرستد.

:::info
این مسیر برای providerهای OpenAI-compatible فعال است؛ مانند `openai`، `groq`، `togetherai`، `openrouter`، `sambanova`، `deepinfra` و `fireworks`. APIهای بومی Google Speech، AWS Transcribe یا Azure Speech قرارداد متفاوتی دارند و در این endpoint فقط بعد از اضافه‌شدن adapter اختصاصی پشتیبانی می‌شوند.
:::

## چه زمانی استفاده کنیم؟

از `Speech to Text` استفاده کنید وقتی می‌خواهید:

- پیام صوتی کاربر را به متن تبدیل کنید.
- تماس‌های پشتیبانی را قابل جست‌وجو کنید.
- متن جلسه را برای خلاصه‌سازی به `Chat Completions` بدهید.
- فایل صوتی را به داده قابل پردازش در سیستم خود تبدیل کنید.

اگر هدف شما ترجمه گفتار به زبان دیگر است، [Audio Translation](/supported-apis/audio-translation) را ببینید. اگر هدف تولید فایل صوتی از متن است، [Text to Speech](/supported-apis/text-to-speech) مسیر جداگانه‌ای دارد.

## فیلدهای درخواست

| فیلد | وضعیت | توضیح |
| --- | --- | --- |
| `model` | اجباری | شناسه مدل صوتی مجاز در گدارAI. |
| `file` | اجباری | فایل صوتی ورودی. |
| `language` | اختیاری | زبان گفتار، مثل `fa` یا `en`. اگر زبان را می‌دانید ارسال کنید. |
| `prompt` | اختیاری | راهنمای کوتاه برای واژه‌های خاص، نام محصول یا زمینه مکالمه. |
| `response_format` | اختیاری | یکی از `json`، `text`، `srt`، `verbose_json`، `vtt` یا `diarized_json`. مقدار پیش‌فرض `json` است. |
| `timestamp_granularities[]` | اختیاری | مقدارهای `word` یا `segment`. فقط وقتی معتبر است که `response_format=verbose_json` باشد. |
| `temperature` | اختیاری | عددی بین `0` و `1`، اگر مدل provider پشتیبانی کند. |
| `stream` | اختیاری | اگر `true` باشد، پاسخ SSE provider به صورت stream عبور داده می‌شود. |
| `include[]` | اختیاری | گزینه‌های تکمیلی provider، مانند `logprobs`، وقتی مدل پشتیبانی کند. |
| `chunking_strategy` | اختیاری | تنظیمات chunking برای مدل‌هایی که پردازش طولانی‌تر یا VAD دارند. |
| `known_speaker_names[]` | اختیاری | نام speakerهای شناخته‌شده برای مدل‌هایی که diarization را پشتیبانی می‌کنند. |
| `known_speaker_references[]` | اختیاری | referenceهای speaker برای providerهایی که این قابلیت را دارند. |

:::tip
اگر زمان‌بندی واژه یا segment می‌خواهید، `response_format` را روی `verbose_json` بگذارید و `timestamp_granularities[]` را ارسال کنید. همه providerها همه سطح‌های زمان‌بندی را پشتیبانی نمی‌کنند.
:::

## خروجی

در حالت `json` خروجی ساده معمولاً متن پیاده‌شده را برمی‌گرداند:

```json
{
  "text": "سلام، این یک نمونه پیام صوتی برای آزمایش است."
}
```

در `verbose_json` پاسخ می‌تواند شامل segment، زمان‌بندی، زبان، مدت فایل و usage باشد:

```json
{
  "text": "سلام دنیا",
  "language": "fa",
  "duration": 2.4,
  "segments": [
    {
      "id": 0,
      "start": 0,
      "end": 2.4,
      "text": "سلام دنیا"
    }
  ],
  "usage": {
    "type": "tokens",
    "input_tokens": 14,
    "output_tokens": 45,
    "total_tokens": 59
  }
}
```

اگر `response_format` را `text`، `srt` یا `vtt` بگذارید، بدنه پاسخ ممکن است متن خام باشد. گدارAI `Content-Type` و بدنه provider را برای پاسخ موفق حفظ می‌کند.

## Streaming

برای مدل‌هایی که transcription streaming را پشتیبانی می‌کنند، `stream=true` را در فرم بفرستید:

```bash
curl --request POST "https://YOUR_WORKSPACE.godarai.ir/v1/audio/transcriptions" \
  --header "Authorization: Bearer YOUR_GODARAI_TOKEN" \
  --form "model=openai:default:gpt-4o-transcribe" \
  --form "stream=true" \
  --form "file=@sample.wav;type=audio/wav"
```

در این حالت پاسخ `text/event-stream` از provider عبور داده می‌شود. اگر مدل انتخابی streaming را پشتیبانی نکند، خطا یا رفتار نهایی را همان provider تعیین می‌کند.

## نکات عملیاتی

- کلید یا مدل باید اجازه `audio_transcription` داشته باشد؛ مدل chat یا image برای این مسیر پذیرفته نمی‌شود.
- فایل صوتی خام، transcript خام و prompt خام در trace و request log ذخیره نمی‌شود؛ فقط طول، hash کوتاه، نوع محتوا و metadata امن ثبت می‌شود.
- مصرف، هزینه و rate limit مثل سایر APIها در گدارAI محاسبه و ثبت می‌شود. اگر provider usage توکنی برگرداند، مصرف نهایی با همان usage reconcile می‌شود.
- اگر provider خطا بدهد، پیام خطا با قالب OpenAI-compatible به client برمی‌گردد.

## کیفیت فایل ورودی

کیفیت تبدیل گفتار به متن به فایل ورودی وابسته است. برای نتیجه بهتر:

- نویز پس‌زمینه را کم کنید.
- اگر ممکن است، از فرمت فشرده‌سازی شدید استفاده نکنید.
- زبان گفتار را مشخص کنید.
- فایل‌های طولانی را به بخش‌های قابل مدیریت تقسیم کنید.
- برای واژه‌های تخصصی، `prompt` کوتاه و دقیق بدهید.

:::warning
فایل صوتی می‌تواند شامل داده شخصی، اطلاعات مشتری یا مکالمه محرمانه باشد. قبل از ارسال، سیاست نگهداری، دسترسی و حذف فایل و متن پیاده‌شده را در اپلیکیشن خود روشن کنید.
:::

## تفاوت با Audio Translation

| موضوع | Speech to Text | Audio Translation |
| --- | --- | --- |
| هدف | تبدیل گفتار به متن همان زبان | ترجمه گفتار به متن زبانی دیگر |
| خروجی | transcript | متن ترجمه‌شده |
| کاربرد | جست‌وجو، خلاصه‌سازی، بایگانی | فهم محتوای صوتی زبان دیگر |

اگر فقط متن فارسی گفتار فارسی را می‌خواهید، `Speech to Text` انتخاب درست است.

## خطاهای رایج

| نشانه | علت محتمل | راه‌حل |
| --- | --- | --- |
| `multipart/form-data content type is required` | درخواست JSON یا فرم نامعتبر ارسال شده است. | فایل را با `multipart/form-data` و فیلد `file` بفرستید. |
| `model is required` | فیلد `model` در فرم نیست. | شناسه مدل مجاز فضای کاری را ارسال کنید. |
| `file is required` | فایل صوتی در فیلد `file` نیست. | نام فیلد فایل را دقیقاً `file` بگذارید. |
| `Model access denied or unsupported` | مدل برای `audio_transcription` مجاز نیست. | مدل صوتی مناسب یا مجوز کلید را بررسی کنید. |
| `timestamp_granularities requires response_format=verbose_json` | زمان‌بندی خواسته‌اید اما خروجی verbose نیست. | `response_format=verbose_json` را اضافه کنید. |
| خطای provider درباره فرمت یا اندازه فایل | فایل با محدودیت مدل سازگار نیست. | فایل را کوتاه‌تر، تمیزتر یا به فرمت رایج‌تر تبدیل کنید. |

## جمع‌بندی

`POST /v1/audio/transcriptions` مسیر استاندارد تبدیل صوت به متن در گدارAI است. این مسیر برای providerهای OpenAI-compatible فایل را به شکل multipart عبور می‌دهد، مدل و دسترسی را کنترل می‌کند، usage را ثبت می‌کند و داده حساس صوتی و transcript را در لاگ خام ذخیره نمی‌کند.
