# RAG مدیریت‌شده

RAG مدیریت‌شده گدارAI اسناد شما را به یک مسیر ثابت متصل می‌کند:

```text
Retrieval → Rerank → Context Packing → Generation → Citation Validation
```

این قابلیت برای پرسش‌وپاسخ مستندات طراحی شده است. پاسخ نهایی فقط از بخش‌های بازیابی‌شده ساخته می‌شود و هر ادعا باید با ارجاعی مانند `[1]` همراه باشد. اگر شواهد کافی نباشد، پاسخ با `refusal: true` برمی‌گردد.

:::info
این قابلیت یک افزونه سازمانی است. پیش از ساخت پایگاه دانش باید `rag.enabled` و سهمیه‌های مربوط به آن برای محیط اختصاصی سازمان فعال شده باشند.
:::

## ساخت پایگاه دانش

یک پایگاه دانش بسازید:

<ApiCodeTabs
  endpoint="/api/v1/knowledge-bases"
  groupId="managed-rag-create-kb"
  body={{
    name: "راهنمای پشتیبانی",
    description: "پاسخ‌های تأییدشده تیم پشتیبانی",
  }}
/>

پاسخ موفق با کد `201` شامل شناسه `id` و نسخه پروفایل `rag_profile_revision` است. این شناسه را برای بارگذاری سند و بازیابی نگه دارید.

## افزودن سند

برای متن دستی، درخواست JSON را به مسیر زیر بفرستید:

```http
POST /api/v1/knowledge-bases/{knowledge_base_id}/documents
Content-Type: application/json

{
  "title": "شرایط بازگشت وجه",
  "text": "بازگشت وجه پس از تأیید درخواست انجام می‌شود."
}
```

برای فایل، همان مسیر را با `multipart/form-data` و فیلد `file` فراخوانی کنید. فایل‌های `PDF`، `DOCX`، `TXT` و `HTML` پذیرفته می‌شوند و سقف هر فایل ۲۵ مگابایت است. اگر PDF متن قابل استفاده نداشته باشد، OCR چندزبانه با پشتیبانی فارسی به‌صورت خودکار اجرا می‌شود.

سند پس از پذیرش با یکی از این وضعیت‌ها پردازش می‌شود:

```text
queued → scanning → parsing → chunking → embedding → indexing → ready
```

فقط نسخه‌ای که به `ready` رسیده است در بازیابی شرکت می‌کند. فایل آلوده، قالب نامعتبر، بایگانی فشرده غیرعادی یا خروجی استخراج کم‌کیفیت با خطای امن رد می‌شود. پاسخ سند آماده، زبان تشخیص‌داده‌شده را در `detected_language` نشان می‌دهد.

:::warning
حذف سند آن را بی‌درنگ از بازیابی خارج می‌کند. پاک‌سازی کامل فایل و بردارها به‌صورت پس‌زمینه انجام می‌شود و بازگشت‌پذیر نیست.
:::

## اجرای بازیابی

در هر درخواست می‌توانید از یک تا پنج پایگاه دانش استفاده کنید:

<ApiCodeTabs
  endpoint="/v1/retrieval"
  groupId="managed-rag-retrieval"
  body={{
    query: "شرایط بازگشت وجه چیست؟",
    knowledge_base_ids: ["11111111-1111-4111-8111-111111111111"],
  }}
/>

پروفایل `rag-v2-fa` جست‌وجوی برداری و واژگانی را ترکیب می‌کند. جست‌وجوی واژگانی برای نام‌ها، کدها، عددها و شکل‌های مختلف حروف و نیم‌فاصله فارسی مفید است. پاسخ شامل `request_id`، نسخه پروفایل، میزان مصرف و حداکثر هشت بخش بازچینی‌شده است. هر بخش این اطلاعات را دارد:

- `citation_id` برای ارجاع در پاسخ؛
- شناسه پایگاه دانش، سند و نسخه سند؛
- عنوان، صفحه، سرفصل و متن؛
- امتیاز بازیابی و امتیاز بازچینی.

بازچینی نتایج اجباری است. اگر سرویس `Rerank` در دسترس نباشد، گدارAI پاسخ ناقص تولید نمی‌کند و خطای `503` برمی‌گرداند.

## ساخت و انتشار چت‌بات

چت‌بات را در `/api/v1/chatbots` بسازید و یک تا پنج `knowledge_base_ids` به آن بدهید. حالت دسترسی پیش‌فرض `private` است و مقدار `retention_days` فقط می‌تواند `0`، `7` یا `30` باشد.

برای زبان و فرهنگ پاسخ این دو فیلد را تنظیم کنید:

- `default_locale`: مقدار `fa-IR` یا `en-US`؛ مقدار پیش‌فرض `fa-IR` است.
- `answer_language`: مقدار `query` برای پاسخ هم‌زبان با پرسش، `fa` برای پاسخ همیشگی فارسی یا `en` برای پاسخ همیشگی انگلیسی.

در حالت فارسی، چت‌بات از نثر طبیعی فارسی استفاده می‌کند. شناسه‌ها، تاریخ‌ها و واحد پول مطابق شاهد باقی می‌مانند؛ تبدیل خودکار تاریخ شمسی و میلادی یا ریال و تومان انجام نمی‌شود. مبلغ دارای واحد پول و تاریخ عددی فقط وقتی پذیرفته می‌شود که همان مقدار در Context وجود داشته باشد؛ در غیر این صورت پاسخ یک‌بار بازتولید و سپس به امتناع امن تبدیل می‌شود.

برای انتشار نسخه تغییرناپذیر، این مسیر را فراخوانی کنید:

```http
POST /api/v1/chatbots/{chatbot_id}/publish
```

انتشار فقط وقتی موفق است که همه پایگاه‌های دانش انتخاب‌شده دست‌کم یک سند آماده داشته باشند. تغییر پیش‌نویس، نسخه منتشرشده را تغییر نمی‌دهد؛ برای اعمال تغییر باید نسخه تازه‌ای منتشر کنید.

## دریافت پاسخ دارای ارجاع

پس از انتشار، از `public_id` استفاده کنید:

```http
POST /v1/chatbots/{public_id}/responses
Content-Type: application/json

{
  "message": "شرایط بازگشت وجه چیست؟",
  "session_id": "OPTIONAL_SESSION_ID",
  "stream": false
}
```

پاسخ موفق نمونه:

```json
{
  "request_id": "rag_...",
  "trace_id": "rag_...",
  "session_id": "...",
  "answer": "بازگشت وجه پس از تأیید درخواست انجام می‌شود [1].",
  "citations": [
    {
      "id": "1",
      "document_id": "22222222-2222-4222-8222-222222222222",
      "title": "شرایط بازگشت وجه",
      "quote": "بازگشت وجه پس از تأیید درخواست انجام می‌شود."
    }
  ],
  "refusal": false,
  "actual_model": "..."
}
```

برای چت‌بات خصوصی، ابتدا از `/api/v1/chatbots/{chatbot_id}/session-tokens` یک JWT کوتاه‌عمر بگیرید و آن را با `Authorization: Bearer ...` بفرستید. بیشترین زمان اعتبار توکن یک ساعت است.

اگر `stream` برابر `true` باشد، گدارAI فقط رویدادهای وضعیت `retrieving` و `reranking` را می‌فرستد. پاسخ نهایی پس از اعتبارسنجی ارجاع، یک‌جا در رویداد `final` ارسال می‌شود؛ توکن‌های پاسخ پیش از اعتبارسنجی نمایش داده نمی‌شوند.

## اتصال به Open WebUI

هر چت‌بات منتشرشده یک سطح سازگار با OpenAI Chat Completions دارد. در Open WebUI از بخش **Admin Settings → Connections → OpenAI** یک اتصال جدید با این مشخصات بسازید:

```text
Base URL: https://API_HOST/v1/chatbots/{public_id}/openai
API Key:  public                         # چت‌بات عمومی
API Key:  {short-lived-session-token}   # چت‌بات خصوصی
```

Open WebUI مدل را از `GET /models` شناسایی می‌کند و درخواست را به `POST /chat/completions` می‌فرستد. شناسه مدل همان `public_id` چت‌بات است. برای چت‌بات خصوصی، API Key را از صفحه «تست چت‌بات» بسازید؛ کلید حداکثر یک ساعت اعتبار دارد و فقط همان یک‌بار نمایش داده می‌شود.

شناسه‌های `chat_id` و `session_id` ارسالی Open WebUI به Session داخلی نگاشت می‌شوند. `chat_id` اولویت دارد تا Context هر گفت‌وگو مستقل بماند و گفت‌وگوهای مختلف یک کاربر با هم ترکیب نشوند.

درخواست‌های `stream: true` نیز پذیرفته می‌شوند، اما متن نهایی به‌دلیل الزام Citation Validation در یک Delta اتمیک ارسال می‌شود. منابع معتبر در انتهای پاسخ Markdown نمایش داده می‌شوند و نسخه ساختاریافته آن‌ها نیز در فیلد توسعه‌یافته `citations` قرار می‌گیرد.

:::warning
اتصال OpenAI-compatible همان محدودیت سهمیه، Rate Limit و Origin Allowlist مسیر اصلی چت‌بات را اجرا می‌کند. API Key چت‌بات خصوصی را به‌عنوان کلید دائمی نگه ندارید.
:::

## خطاهای مهم

| کد | وضعیت HTTP | معنی |
|---|---:|---|
| `rag_addon_required` | `403` | افزونه RAG برای سازمان فعال نیست. |
| `rag_entitlement_required` | `403` | سهمیه یا مجوز لازم وجود ندارد. |
| `rag_query_quota_exceeded` | `429` | سهمیه ماهانه پرس‌وجو تمام شده است. |
| `file_rejected` | `422` | فایل از بررسی قالب یا امنیت عبور نکرده است. |
| `private_chatbot_token_required` | `401` | توکن چت‌بات خصوصی وجود ندارد یا معتبر نیست. |
| `origin_not_allowed` | `403` | مبدأ درخواست در فهرست مجاز چت‌بات نیست. |
| `rag_dependency_unavailable` | `503` | بازیابی، بازچینی یا تولید پاسخ در دسترس نیست. |

نبود شواهد خطای زیرساختی نیست. در این حالت پاسخ HTTP موفق است و `refusal` مقدار `true` دارد.

## سازگاری متن فارسی

گدارAI متن نمایشی سند را از متن ایندکس جدا نگه می‌دارد. Quote ارجاع از متن نمایشی ساخته می‌شود، اما برای جست‌وجو این تفاوت‌ها یکسان‌سازی می‌شوند:

- حروف عربی و فارسی `ی/ي` و `ک/ك`؛
- رقم‌های فارسی، عربی و لاتین؛
- فاصله، نیم‌فاصله و نویسه‌های نامرئی؛
- اعراب، کشیده و نشانه‌های نگارشی فارسی؛
- شکل‌های رایج پیشوند و پسوند، مانند «می‌رود» و «می رود».

شماره صفحه، تیتر، فهرست و ردیف جدول هنگام استخراج حفظ می‌شوند. اندازه Chunk با tokenizer واقعی مدل Embedding محاسبه می‌شود، نه با شمارش ساده واژه‌ها.
