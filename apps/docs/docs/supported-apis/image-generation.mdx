# Image Generation

`Image Generation` برای تولید تصویر از روی prompt متنی استفاده می‌شود. در گدارAI این قابلیت از طریق قرارداد OpenAI-compatible ارائه می‌شود و نقطه ورود اصلی آن این endpoint است:

```text
POST /v1/images/generations
```

اگر می‌خواهید از توضیح متنی، تصویر تبلیغاتی، تصویر مفهومی، تصویر محصول یا نمونه‌های بصری برای workflowهای داخلی بسازید، این API مسیر استاندارد شماست.

## وضعیت فعلی در گدارAI

در پیاده‌سازی فعلی `services/control-plane`:

- `POST /v1/images/generations` واقعاً پیاده‌سازی شده است
- request بعد از auth، budget و rate-limit از gateway عبور می‌کند
- مدل انتخابی بر اساس routing و deploymentهای مجاز tenant resolve می‌شود
- پاسخ provider بدون تغییرات بزرگ در contract به کاربر برگردانده می‌شود

نکته مهم:

- در implementation فعلی، gateway بیشتر نقش لایه سازگار (Compatibility Layer) و pass-through را دارد
- پشتیبانی واقعی هر model به deploymentی بستگی دارد که برای tenant شما تعریف شده است

پس بهتر است به‌جای اتکا به یک جدول ثابت جهانی، از modelهایی استفاده کنید که در محیط گدارAI شما به‌عنوان `image_generation` فعال شده‌اند.

## این endpoint چه مسئله‌ای را حل می‌کند؟

بدون این endpoint، برای هر provider باید API جداگانه، auth جدا، contract جدا و منطق حسابداری جدا بنویسید. GodarAI این پیچیدگی را کم می‌کند:

- یک ورودی استاندارد شبیه OpenAI می‌گیرید
- احراز هویت و کنترل دسترسی را در gateway انجام می‌دهید
- budget و rate limit را در همان لایه مرکزی اعمال می‌کنید
- usage و tracing را به‌صورت یکپارچه نگه می‌دارید

## چه زمانی از Image Generation استفاده کنیم؟

این endpoint برای سناریوهایی مثل این مناسب است:

- تولید تصویر از متن برای پنل‌های محصول
- ساخت بنر، mockup یا concept art
- تولید تصویر برای محتوای آموزشی یا بازاریابی
- ساخت asset اولیه برای workflowهای طراحی

اگر هدف شما ویرایش تصویر موجود یا ساخت variation از تصویر قبلی است، به endpointهای تخصصی‌تر همان خانواده نیاز دارید، نه `generations`.

## شروع سریع

ساده‌ترین روش، استفاده از SDK رسمی OpenAI است:

```python
from openai import OpenAI
import base64

client = OpenAI(
    api_key="YOUR_GODARAI_API_KEY",
    base_url="YOUR_GODARAI_BASE_URL",
)

response = client.images.generate(
    model="openai:default:gpt-image-1",
    prompt="یک پوستر مینیمال از آینده هوش مصنوعی با تایپوگرافی فارسی",
    n=1,
    size="1024x1024"
)

item = response.data[0]

if getattr(item, "url", None):
    print(item.url)

if getattr(item, "b64_json", None):
    image_bytes = base64.b64decode(item.b64_json)
    with open("godarai-image.png", "wb") as f:
        f.write(image_bytes)
```

## برای استفاده به چه چیزهایی نیاز دارید؟

- `base_url` گیت‌وی گدارAI
- `api_key` معتبر از نوع `PAT` یا `VAT`
- یک model مجاز از نوع `image_generation`

در backend فعلی، دسترسی model بر اساس نوع `image_generation` بررسی می‌شود. اگر مدل موردنظر در scope شما فعال نباشد، request رد می‌شود.

## ساختار پایه request

در حالت معمول، این فیلدها مهم‌ترین بخش request شما هستند:

- `model`
- `prompt`
- `n`
- `size`
- `quality`
- `response_format`

نمونه:

```json
{
  "model": "openai:default:gpt-image-1",
  "prompt": "یک داشبورد مدرن برای مدیریت API key با رنگ‌های حرفه‌ای",
  "n": 1,
  "size": "1024x1024",
  "quality": "high",
  "response_format": "url"
}
```

## پارامترهای متداول

در implementation فعلی، gateway این metadataها را از request استخراج و برای tracing و billing context ثبت می‌کند:

- `size`
- `quality`
- `response_format`
- `n`

همچنین طول prompt و hash امن آن برای observability ثبت می‌شود، بدون این‌که خود متن خام prompt در traceها لو برود.

## فرمت پاسخ

خروجی معمولاً در یکی از این دو شکل برمی‌گردد:

- `url`
- `b64_json`

نمونه:

```json
{
  "created": 1713833628,
  "data": [
    {
      "url": "https://cdn.example.com/generated.png",
      "b64_json": null
    }
  ]
}
```

یا در بعضی providerها:

```json
{
  "created": 1713833628,
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAA...",
      "mime_type": "image/png"
    }
  ]
}
```

بهتر است client شما هر دو حالت را پشتیبانی کند، چون provider و model ممکن است رفتار متفاوتی داشته باشند.

## نکته مهم درباره providerها

در متن مرجع TrueFoundry، providerهای مختلفی برای image generation فهرست شده‌اند. اما در گدارAI بهتر است این موضوع را این‌طور ببینید:

- gateway به deploymentهای مختلف route می‌کند
- contract عمومی شبیه OpenAI باقی می‌ماند
- قابلیت واقعی هر model به provider و deployment configured شما وابسته است

یعنی اگر مدل image برای tenant شما از طریق OpenAI، Azure، Bedrock، Vertex یا provider دیگری پیکربندی شده باشد، همین endpoint می‌تواند نقطه ورود یکدست شما باشد؛ ولی پشتیبانی دقیق پارامترها را باید با مدل configured خودتان بسنجید.

## بودجه و هزینه

در backend فعلی، درخواست‌های image generation هم از budget check عبور می‌کنند و پس از موفقیت، هزینه از wallet tenant کسر می‌شود.

نکته مهم:

- برآورد هزینه در این بخش فعلاً با یک fallback ساده انجام می‌شود
- metadataهایی مثل `provider_cost_in_usd_ticks` اگر از provider برگردند، در logging داخلی ثبت می‌شوند

پس برای workloadهای تصویری سنگین، بهتر است usage واقعی را در محیط خودتان مانیتور کنید و rollout را با احتیاط انجام دهید.

## امنیت و حریم خصوصی در observability

در تست‌های فعلی پروژه یک نکته ارزشمند دیده می‌شود:

- مقدار کامل `b64_json` در traceها نگه‌داری نمی‌شود
- URLهای خصوصی تصویر redact می‌شوند
- خود prompt خام هم در traceها به‌صورت مستقیم لاگ نمی‌شود

این موضوع برای تیم‌هایی که با دارایی‌های حساس یا محتوای داخلی کار می‌کنند مهم است.

## چند خطای رایج

چند خطای مهمی که ممکن است ببینید:

- `model is required`
- `Model access denied or unsupported for image generation`
- `No available deployment for model: ...`
- خطاهای provider که به‌شکل passthrough برگردانده می‌شوند

در عمل اگر request شما از نظر contract درست است ولی هنوز خطا می‌گیرید، معمولاً باید این سه چیز را بررسی کنید:

- model درست است یا نه
- آن model در scope شما مجاز هست یا نه
- برای آن model deployment فعال وجود دارد یا نه

## چند توصیه عملی برای کاربران گدارAI

### client را برای هر دو حالت `url` و `b64_json` آماده کنید

بعضی مدل‌ها لینک برمی‌گردانند و بعضی دیگر تصویر را base64 می‌دهند.

### برای production از VAT استفاده کنید

اگر این endpoint در سرویس backend یا pipeline سازمانی مصرف می‌شود، virtual account token انتخاب بهتری از PAT انسانی است.

### promptها را دقیق و outcome-oriented بنویسید

در image generation، کیفیت خروجی معمولاً بیشتر از هر چیز به کیفیت prompt وابسته است.

### rollout را با modelهای مجاز tenant خودتان انجام دهید

به‌جای اتکا به نام modelهای عمومی اینترنت، با همان model aliasهایی کار کنید که در گدارAI شما واقعاً configured شده‌اند.

## جمع‌بندی

`Image Generation` در گدارAI از مسیر `POST /v1/images/generations` در دسترس است و یک لایه OpenAI-compatible برای تولید تصویر از متن فراهم می‌کند. این endpoint برای ساخت workflowهای تصویری بسیار کاربردی است، اما رفتار دقیق پارامترها و فرمت خروجی را باید بر اساس deployment و provider واقعی tenant خودتان ارزیابی کنید.
