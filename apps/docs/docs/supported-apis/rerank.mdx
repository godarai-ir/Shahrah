# Rerank

`Rerank` نتایج اولیه جست‌وجو یا بازیابی را دوباره امتیازدهی می‌کند و موارد مرتبط‌تر را بالاتر می‌آورد. این API معمولاً بعد از `Embeddings`، جست‌وجوی برداری یا جست‌وجوی کلیدواژه‌ای استفاده می‌شود.

## Rerank چه مسئله‌ای را حل می‌کند؟

در بسیاری از سیستم‌های جست‌وجو، مرحله اول تعداد زیادی نتیجه اولیه برمی‌گرداند. این نتایج لزوماً بهترین ترتیب را ندارند. `Rerank` این کار را انجام می‌دهد:

1. یک `query` یا پرسش می‌گیرد.
2. چند `documents` یا نتیجه اولیه دریافت می‌کند.
3. برای هر نتیجه، امتیاز ارتباط محاسبه می‌کند.
4. نتایج را بر اساس ارتباط واقعی‌تر مرتب می‌کند.

این الگو برای RAG، جست‌وجوی دانش سازمانی، پرسش‌وپاسخ مستندات و مرکز پشتیبانی بسیار کاربردی است.

## چه زمانی استفاده کنیم؟

از `Rerank` استفاده کنید وقتی:

- مرحله بازیابی اولیه نتیجه‌های زیاد یا نزدیک به هم برمی‌گرداند.
- کیفیت چند نتیجه اول برای تجربه کاربر بسیار مهم است.
- متن‌ها فارسی، انگلیسی یا ترکیبی هستند و شباهت برداری به‌تنهایی کافی نیست.
- می‌خواهید پیش از ارسال متن به مدل پاسخ‌ساز، فقط بهترین بخش‌ها را نگه دارید.

اگر فقط چند سند محدود دارید و ترتیب آن‌ها روشن است، Rerank ممکن است هزینه و زمان اضافی ایجاد کند.

## جایگاه در گدارAI

`Rerank` یک قابلیت مستقل مدل است و فعال‌بودن آن به مدل‌ها و ارائه‌دهنده‌های متصل در فضای کاری شما بستگی دارد. اگر این قابلیت در محیط شما فعال باشد، مسیر دقیق و مدل‌های مجاز در همان محیط مشخص می‌شود. قرارداد مفهومی رایج چنین شکلی دارد:

```text
POST /rerank
```

## ساختار درخواست

```json
{
  "model": "cohere:default:rerank-multilingual-v3.0",
  "query": "تهران پایتخت کدام کشور است؟",
  "documents": [
    "تهران پایتخت ایران است.",
    "آسمان امروز آبی است.",
    "مشهد یکی از شهرهای بزرگ ایران است."
  ],
  "top_n": 2
}
```

`top_n` مشخص می‌کند چند نتیجه برتر را می‌خواهید. اگر تعداد نتیجه اولیه زیاد است، مقدار `top_n` را با نیاز واقعی رابط کاربری یا مدل پاسخ‌ساز هماهنگ کنید.

## شکل پاسخ

```json
{
  "results": [
    {
      "index": 0,
      "relevance_score": 0.98
    },
    {
      "index": 2,
      "relevance_score": 0.41
    }
  ]
}
```

`index` به جایگاه سند در آرایه ورودی اشاره می‌کند. بنابراین در سرویس خودتان نگاشت بین سند اصلی، شناسه داخلی و نتیجه Rerank را نگه دارید.

## تفاوت با Embeddings

| موضوع | Embeddings | Rerank |
| --- | --- | --- |
| نقش | ساخت نمایش برداری متن | بازمرتب‌سازی نتایج اولیه |
| زمان استفاده | قبل از جست‌وجو یا هنگام ورود پرسش | بعد از بازیابی اولیه |
| خروجی | بردار عددی | امتیاز و ترتیب نتایج |
| هدف | پیدا کردن گزینه‌های نزدیک | انتخاب دقیق‌تر بین گزینه‌های نزدیک |

یک الگوی خوب این است: با Embeddings پنجاه نتیجه نزدیک بگیرید، با Rerank ده نتیجه برتر را انتخاب کنید، سپس فقط چند بخش نهایی را به مدل پاسخ‌ساز بدهید.

## نکته‌های آموزشی

- Rerank جایگزین جست‌وجوی اولیه نیست؛ مکمل آن است.
- تعداد اسناد ورودی را بی‌دلیل زیاد نکنید، چون هزینه و زمان پاسخ بالا می‌رود.
- کیفیت را با داده واقعی فارسی خودتان بسنجید؛ رتبه‌بندها روی همه دامنه‌ها یکسان عمل نمی‌کنند.
- اگر این API هنوز در محیط شما فعال نیست، لایه داخلی خود را طوری طراحی کنید که بعداً بتوانید Rerank گدارAI را جایگزین کنید.

## جمع‌بندی

`Rerank` برای بالا بردن دقت نتایج جست‌وجو و RAG استفاده می‌شود. آن را بعد از بازیابی اولیه قرار دهید، تعداد گزینه‌ها را کنترل کنید و همیشه کیفیت را با پرسش‌ها و اسناد واقعی محصول خود بسنجید.
