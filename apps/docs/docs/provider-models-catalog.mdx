# جست‌وجو و فیلتر مدل‌ها

فهرست مدل‌ها نقطه شروع عملی برای پیدا کردن گزینه مناسب است. در این صفحه می‌توانید نام مدل یا ارائه‌دهنده را جست‌وجو کنید، نوع ورودی و خروجی را فیلتر کنید، محدوده پنجره زمینه و قیمت ورودی را مشخص کنید و بعد مدل‌های نزدیک به نیازتان را باز کنید یا به مقایسه اضافه کنید.

برای شروع از این مسیر استفاده کنید:

[http://DOMAIN/catalog/models](http://DOMAIN/catalog/models)

:::info
در همه نمونه‌ها، `DOMAIN` جای دامنه کاتالوگ شماست. اگر کاتالوگ روی دامنه داخلی یا دامنه اختصاصی سازمان شما منتشر شده، همان مقدار را جایگزین کنید.
:::

## فیلترهای اصلی

| نیاز | فیلتر یا مسیر | چه زمانی استفاده شود |
| --- | --- | --- |
| جست‌وجوی نام مدل، ارائه‌دهنده یا توضیح | [http://DOMAIN/catalog/models?q=support](http://DOMAIN/catalog/models?q=support) | وقتی نام دقیق مدل را نمی‌دانید یا دنبال یک خانواده کاربردی هستید. |
| محدود کردن به یک ارائه‌دهنده | [http://DOMAIN/catalog/models?provider=openai](http://DOMAIN/catalog/models?provider=openai) | وقتی می‌خواهید فقط مدل‌های یک ارائه‌دهنده را ببینید. |
| مدل‌های متن به متن | [http://DOMAIN/catalog/models?input_modalities=text&output_modalities=text](http://DOMAIN/catalog/models?input_modalities=text&output_modalities=text) | برای چت، خلاصه‌سازی، دسته‌بندی، تولید پاسخ و سناریوهای متنی. |
| مدل‌های متن به تصویر | [http://DOMAIN/catalog/models?input_modalities=text&output_modalities=image](http://DOMAIN/catalog/models?input_modalities=text&output_modalities=image) | برای تولید تصویر از توضیح متنی، بنر، تصویر محصول یا محتوای کمپین. |
| مدل‌های دارای پنجره زمینه بزرگ | [http://DOMAIN/catalog/models?min_context_window=128000](http://DOMAIN/catalog/models?min_context_window=128000) | برای مکالمه طولانی، تحلیل چند سند یا بررسی تاریخچه تیکت. |
| مدل‌های با سقف قیمت ورودی | [http://DOMAIN/catalog/models?max_input_price=2](http://DOMAIN/catalog/models?max_input_price=2) | وقتی هزینه ورودی برای حجم زیاد درخواست مهم است. |

:::tip
فیلترها را از نیاز محصول شروع کنید، نه از نام مدل. برای مثال اگر قرار است تیکت‌های طولانی پشتیبانی خلاصه شوند، اول نوع ورودی/خروجی و پنجره زمینه را محدود کنید؛ بعد سراغ قیمت و ارائه‌دهنده بروید.
:::

در فیلتر قیمت ورودی، عددها را بر اساس قیمت دلاری به ازای یک میلیون توکن وارد کنید. ممکن است در تنظیمات نمایش، قیمت‌ها را با واحد دیگری مثل ریال یا تومان ببینید؛ اما پیوند عمیق فیلتر همچنان باید از پارامترهای فنی کاتالوگ استفاده کند.

## خواندن کارت مدل

هر کارت مدل چند نشانه سریع دارد:

| داده روی کارت | برداشت درست |
| --- | --- |
| نام و شناسه کامل مدل | برای شناخت و ارجاع فنی. شناسه‌ای مثل `openai/gpt-4o` معمولاً در لینک مقایسه و API کاتالوگ استفاده می‌شود. |
| ارائه‌دهنده | نشان می‌دهد مدل از کدام سرویس بالادستی آمده است. |
| وضعیت | اگر مدل `preview` یا `deprecated` باشد، پیش از انتخاب برای محیط عملیاتی بیشتر بررسی کنید. |
| پنجره زمینه و بیشینه خروجی | نشان می‌دهد مدل چقدر ورودی می‌پذیرد و چقدر می‌تواند پاسخ تولید کند. |
| قیمت ورودی | برای تخمین هزینه سناریوهای پرترافیک مهم است، اما هزینه خروجی را هم در جزئیات مدل ببینید. |
| قابلیت‌ها | سرنخ اولیه درباره توانایی‌هایی مثل چندوجهی بودن، ابزارخوانی، خروجی ساخت‌یافته یا بینایی. |

:::warning
مدل ارزان‌تر همیشه انتخاب کم‌هزینه‌تر نیست. اگر مدل برای رسیدن به پاسخ قابل قبول به تلاش دوباره، پرامپت طولانی‌تر یا پردازش تکمیلی نیاز داشته باشد، هزینه واقعی محصول می‌تواند بیشتر شود.
:::

## باز کردن جزئیات مدل

وقتی گزینه‌ای نزدیک به نیازتان پیدا کردید، صفحه جزئیات مدل را باز کنید. این صفحه معمولاً اطلاعات دقیق‌تری دارد:

- مشخصات پایه مثل وضعیت، تاریخ انتشار، تاریخ قطع دانش و پنجره زمینه.
- وضعیت ارائه‌دهنده، مستندات رسمی، سیاست حریم خصوصی و قابلیت‌هایی مثل BYOK یا مسیریابی منطقه‌ای.
- نوع‌های ورودی و خروجی.
- قابلیت‌ها و پارامترهای پشتیبانی‌شده.
- قیمت‌ها، تاریخ اثر قیمت و منبع داده.

## سناریوهای رایج فیلتر

| سناریو | مسیر پیشنهادی |
| --- | --- |
| پاسخ‌گویی پشتیبانی با متن طولانی | اول مدل‌های متن به متن را ببینید، سپس `min_context_window` را بالا ببرید و قیمت خروجی را در جزئیات بررسی کنید. |
| تحلیل تصویر رسید یا تصویر کالا | مدل‌هایی را پیدا کنید که ورودی تصویر و خروجی متن دارند؛ سپس صفحه جزئیات و مستندات رسمی مدل را بخوانید. |
| تولید تصویر برای کمپین | مدل‌های متن به تصویر را فیلتر کنید و در جزئیات مدل، قیمت تصویر و محدودیت‌های ارائه‌دهنده را بررسی کنید. |
| تبدیل پیام صوتی به متن | مدل‌های دارای ورودی صوت یا APIهای صوتی را بررسی کنید و بعد صفحه [Speech to Text](/supported-apis/speech-to-text) را بخوانید. |

## ارتباط با درگاه و مدل مجازی

بعد از انتخاب مدل در کاتالوگ، معمولاً یکی از دو مسیر را ادامه می‌دهید:

- اگر فقط تست می‌کنید، مدل مجاز را از مسیر درگاه با توکن مناسب فراخوانی کنید.
- اگر می‌خواهید نام مدل در کد محصول پایدار بماند، برای آن [مدل مجازی](/virtual-model) بسازید و اپلیکیشن را به شناسه مدل مجازی وصل کنید.

:::tip
برای تصمیم‌های عملیاتی، لینک جزئیات مدل را کنار لینک لاگ یا متریک نگه دارید. وقتی هزینه یا کیفیت پاسخ تغییر می‌کند، تیم سریع‌تر می‌فهمد مسئله از مدل، ارائه‌دهنده، پرامپت، حجم ورودی یا مسیر اجرای درخواست بوده است.
:::
