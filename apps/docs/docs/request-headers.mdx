# Headerهای درخواست

در گدارAI، بخشی از رفتار request فقط از طریق body کنترل نمی‌شود؛ بعضی capabilityها و metadataهای عملیاتی از طریق headerها منتقل می‌شوند. این headerها برای کارهایی مثل:

- احراز هویت
- trace و observability
- tenant hint
- cache behavior
- guardrail selection
- دریافت metadata هزینه

استفاده می‌شوند.

## مهم‌ترین header: `Authorization`

برای استفاده از APIهای گدارAI، همیشه باید API key خود گدارAI را در هدر `Authorization` بفرستید:

```text
Authorization: Bearer YOUR_GODARAI_API_KEY
```

این header پایه‌ای‌ترین header هر request است. بدون آن، request احراز هویت نمی‌شود.

## headerهای واقعی پروژه در نسخه فعلی

در implementation فعلی `services/control-plane`، headerهای canonical اصلی این‌ها هستند:

| Header | کاربرد |
| --- | --- |
| `x-godarai-trace-id` | تعیین یا حمل trace id |
| `x-godarai-tenant` | tenant hint برای resolve tenant |
| `x-godarai-cache-config` | تنظیم رفتار cache |
| `x-godarai-guardrails` | انتخاب guardrail |
| `x-godarai-guardrails-scope` | scope اجرای guardrail |
| `x-godarai-cost-usd` | هدر پاسخ برای هزینه دلاری |
| `x-godarai-cost-irr` | هدر پاسخ برای هزینه ریالی |
| `x-godarai-cache-status` | هدر پاسخ برای وضعیت cache |
| `x-godarai-cached-trace-id` | هدر پاسخ برای trace منبع cache hit |
| `x-godarai-cache-similarity-score` | هدر پاسخ برای smart cache hit |

## `x-godarai-trace-id`

اگر می‌خواهید یک request را در لاگ‌ها و traceهای خودتان با شناسه‌ای که از قبل دارید correlate کنید، می‌توانید trace id را صریحاً بفرستید:

```text
x-godarai-trace-id: trace_abc123
```

در implementation فعلی:

- اگر این header را بفرستید، gateway از همان استفاده می‌کند
- اگر نفرستید، trace id در gateway ساخته می‌شود
- هدر `x-trace-id` نیز در بعضی مسیرها به‌عنوان مقدار جایگزین شناخته می‌شود

## `x-godarai-tenant`

در معماری چندمستاجری گدارAI، tenant معمولاً از host یا context resolve می‌شود. اما در بعضی سناریوها می‌توان از tenant hint هم استفاده کرد:

```text
x-godarai-tenant: acme
```

نکته مهم:

- این header فقط یک hint است، نه bypass امنیتی
- استفاده مؤثر آن به تنظیمات tenant middleware و `allow_header_hint` بستگی دارد

پس این header را بیشتر برای سناریوهای internal، debugging یا مسیرهای خاص چندمستاجری در نظر بگیرید.

## `x-godarai-cache-config`

برای بعضی درخواست‌ها می‌توانید رفتار حافظه نهان را از طریق هدر مشخص کنید.

نمونه مفهومی:

```text
x-godarai-cache-config: {"type":"simple","ttl":600,"namespace":"production"}
```

این header بیشتر زمانی مهم است که از response cache یا smart cache استفاده می‌کنید.

## `x-godarai-guardrails`

اگر در tenant شما guardrail تعریف شده باشد، می‌توانید انتخاب یا اعمال آن را با header کنترل کنید:

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/pii-redaction"]}
```

اگر header به‌شکل plain string ارسال شود، به‌عنوان فهرست selectorهای ورودی تفسیر می‌شود:

```text
x-godarai-guardrails: guardrails/pii-redaction, guardrails/secrets-detection
```

## `x-godarai-guardrails-scope`

برای تعیین scope اجرای guardrailهای ورودی:

```text
x-godarai-guardrails-scope: last
```

مقادیر معتبر:

- `all`
- `last`

اگر output guardrail لازم دارید، آن را داخل `x-godarai-guardrails` و با کلید `llm_output_guardrails` مشخص کنید. در نسخه فعلی، خروجی stream شده با output guardrail پشتیبانی نمی‌شود.

## headerهای پاسخ مرتبط با cache

اگر از cache استفاده می‌کنید، چند header پاسخ می‌توانند برای debugging مهم باشند:

### `x-godarai-cache-status`

وضعیت cache را نشان می‌دهد. در الگوهای فعلی معمولاً مقادیری مثل این مهم‌اند:

- `hit`
- `miss`
- `bypass`
- `error`

### `x-godarai-cached-trace-id`

اگر پاسخ از cache آمده باشد، ممکن است trace request اصلی را نشان دهد.

### `x-godarai-cache-similarity-score`

در smart cache و hitهای semantic، این header می‌تواند score شباهت را برگرداند.

## headerهای پاسخ مرتبط با هزینه

برای بعضی endpointها، gateway هزینه request را هم در headerهای پاسخ برمی‌گرداند:

- `x-godarai-cost-usd`
- `x-godarai-cost-irr`

این headerها برای dashboard سمت client، debugging هزینه، یا attribution سبک مفیدند. البته برای گزارش‌گیری دقیق‌تر همچنان بهتر است به logging و usage records تکیه کنید.

## چند توصیه عملی

### فقط از هدرهای اصلی گدارAI استفاده کنید

هدرهای عمومی گدارAI با پیشوند `x-godarai-*` تعریف می‌شوند.

### فقط وقتی header اضافه کنید که use case روشن دارید

هر header اضافه، debugging و maintenance را سخت‌تر می‌کند. اگر نیازی به trace id سفارشی یا cache config ندارید، request را ساده نگه دارید.

### response headerها را در client ثبت کنید

اگر روی هزینه، cache یا trace حساس هستید، این headerها را در client log یا observability خودتان capture کنید.

### tenant hint را با احتیاط استفاده کنید

در سیستم چندمستاجری، tenant resolution موضوع حساسی است. این header را فقط وقتی استفاده کنید که واقعاً architecture شما به آن نیاز دارد.

## جمع‌بندی

در گدارAI، مهم‌ترین هدر همیشه `Authorization` است، اما هدرهای دیگری هم برای رد درخواست، حافظه نهان، قواعد محافظ، راهنمای محیط اختصاصی سازمان و فراداده‌های پاسخ وجود دارند. قرارداد عمومی پروژه بر هدرهای `x-godarai-*` استوار است.
