# JSON Schema

گاردریل `json_schema` بررسی می‌کند متن انتخاب‌شده JSON معتبر باشد و با بخش پشتیبانی‌شده از JSON Schema تطابق داشته باشد. این نوع بیشتر برای کنترل پاسخ ساخت‌یافته مدل استفاده می‌شود.

## چه زمانی استفاده کنید؟

از این گاردریل برای این کارها استفاده کنید:

- اطمینان از اینکه پاسخ مدل فقط JSON معتبر است.
- الزام پاسخ به یک شیء یا آرایه JSON.
- اجباری‌کردن چند کلید اصلی در پاسخ.
- کنترل نوع فیلدهای مستقیم، مثل رشته یا عدد.

اگر فقط می‌خواهید وجود یا نبودن چند کلید سطح اول را بررسی کنید، [کلیدهای JSON](/guardrails-json-keys) ساده‌تر است.

## رفتار اجرایی

این نوع فقط از «اعتبارسنجی» (`operation: "validate"`) پشتیبانی می‌کند. کل متن باید JSON معتبر باشد. متن توضیحی کنار JSON، بلوک کد و JSON ناقص پذیرفته نمی‌شود.

بخش پشتیبانی‌شده از JSON Schema شامل این موارد است:

| کلید | رفتار پشتیبانی‌شده |
| --- | --- |
| `type` | نوع مقدار ریشه: `object`، `array`، `string`، `number`، `integer`، `boolean` یا `null`. |
| `required` | وجود کلیدهای لازم در شیء سطح اول. |
| `properties.<key>.type` | نوع فیلدهای مستقیم شیء سطح اول، در صورت وجود آن فیلد. |

## تنظیمات

| عنوان | مقدار API | توضیح |
| --- | --- | --- |
| JSON Schema | `schema` | شیء JSON غیرخالی که ساختار مورد انتظار را تعریف می‌کند. |

## نمونه تعریف

نمونه زیر پاسخ را به یک شیء JSON با دو فیلد `answer` و `confidence` محدود می‌کند:

```json
{
  "slug": "answer-schema",
  "name": "Structured answer schema",
  "type": "json_schema",
  "operation": "validate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "schema": {
      "type": "object",
      "required": ["answer", "confidence"],
      "properties": {
        "answer": {"type": "string"},
        "confidence": {"type": "number"}
      }
    }
  }
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/answer-schema"]}
```

پاسخ زیر پذیرفته می‌شود:

```json
{"answer":"تهران","confidence":0.98}
```

پاسخی که قبل یا بعد از JSON توضیح اضافه داشته باشد، رد می‌شود.

## بررسی نتیجه

اگر متن JSON معتبر نباشد، علت `Response is not valid JSON` ثبت می‌شود. اگر JSON معتبر باشد اما با schema نخورد، علت `JSON schema validation failed` ثبت می‌شود.

## محدودیت‌ها

- این پیاده‌سازی اعتبارسنج کامل استاندارد JSON Schema نیست.
- کلیدهایی مثل `additionalProperties`، `enum`، `items`، `pattern`، بازه عددی و اعتبارسنجی تودرتو اجرا نمی‌شوند.
- نوع ناشناخته در schema باعث ردشدن مقدار نمی‌شود؛ فقط نوع‌های جدول بالا را استفاده کنید.
- هر `choice` خروجی باید جداگانه JSON کامل و معتبر باشد.
- گاردریل خروجی با پاسخ جریانی پشتیبانی نمی‌شود.

## گام بعدی

- برای بررسی ساده نام کلیدها، [کلیدهای JSON](/guardrails-json-keys) را ببینید.
- برای قالب‌دهی خروجی مدل پیش از گاردریل، [Structured Outputs](/supported-apis/chat-completions/structured-outputs) را بخوانید.
