# تعداد کاراکتر

گاردریل `character_count` تعداد کاراکترهای هر متن را بررسی می‌کند. فاصله، خط جدید و علائم نگارشی هم در شمارش قرار می‌گیرند.

## چه زمانی استفاده کنید؟

از این گاردریل برای این کارها استفاده کنید:

- اعمال سقف دقیق‌تر از تعداد کلمه.
- جلوگیری از ورودی یا پاسخ بسیار بزرگ.
- الزام وجود حداقل محتوای متنی.

## رفتار اجرایی

این نوع فقط از «اعتبارسنجی» (`operation: "validate"`) پشتیبانی می‌کند. شمارش بر اساس کاراکترهای Unicode انجام می‌شود؛ بنابراین حروف فارسی هم شمرده می‌شوند. هر متن انتخاب‌شده جداگانه باید داخل بازه باشد.

## تنظیمات

| عنوان | مقدار API | توضیح |
| --- | --- | --- |
| حداقل | `min` | حداقل تعداد کاراکتر مجاز. مقدار باید صفر یا بیشتر باشد. |
| حداکثر | `max` | حداکثر تعداد کاراکتر مجاز. مقدار باید صفر یا بیشتر باشد. |

باید دست‌کم یکی از «حداقل» یا «حداکثر» را وارد کنید. اگر هر دو را وارد می‌کنید، حداقل باید کوچک‌تر یا برابر حداکثر باشد.

## نمونه تعریف

```json
{
  "slug": "response-character-limit",
  "name": "Response character limit",
  "type": "character_count",
  "operation": "validate",
  "enforcement": "audit",
  "enabled": true,
  "config": {
    "min": 1,
    "max": 4000
  }
}
```

## نمونه استفاده

برای کنترل پاسخ غیرجریانی مدل:

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/response-character-limit"]}
```

با «عبور همراه با نشانه‌گذاری»، متن بیرون از بازه فقط با وضعیت `flagged` ثبت می‌شود و پاسخ متوقف نمی‌شود.

## بررسی نتیجه

اگر تعداد کاراکتر بیرون از بازه باشد، علت `character count is outside allowed range` ثبت می‌شود. اگر متن داخل بازه باشد، وضعیت `passed` است.

## محدودیت‌ها

- تعداد کاراکتر با طول بایت و تعداد توکن مدل یکی نیست.
- بعضی ایموجی‌ها یا نشانه‌های ترکیبی ممکن است از چند کاراکتر Unicode ساخته شده باشند.
- گاردریل آماده برای این نوع وجود ندارد؛ باید گاردریل اختصاصی بسازید.
- گاردریل خروجی با پاسخ جریانی پشتیبانی نمی‌شود.
