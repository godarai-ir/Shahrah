# Regex گاردریل

`regex` برای بررسی یا تغییر متن بر اساس الگوهای سفارشی استفاده می‌شود. این گاردریل مناسب داده‌هایی است که در تیم یا سازمان شما، از قالب مشخصی برخوردار هستند؛ مثل شناسه مشتری، شماره پرونده، توکن داخلی یا هر الگوی قابل تعریف با Regex.

## چه زمانی استفاده کنیم؟

از این گاردریل وقتی استفاده کنید که تشخیص با عبارت ثابت کافی نیست و باید الگوی دقیق‌تری داشته باشید.

نمونه‌ی کاربردها:

- مسدودکردن یا ماسک‌کردن شناسه‌های داخلی
- پیدا کردن الگوهای داده‌های محرمانه که در `secrets_detection` پوشش داده نشده‌اند
- حذف مقدارهایی مثل `password=...` یا `customer_id=...`
- اجرای سیاست‌های کنترلی معین پیش از ارسال پرامپت به مدل

## رفتار اجرایی

این نوع از هر دو عملیات پشتیبانی می‌کند:

| اقدام | رفتار |
| --- | --- |
| `validate` | اگر هر الگویی منطبق شود، چک ناموفق می‌شود. |
| `mutate` | matchها با `redaction_text` جایگزین می‌شوند. |

اگر `اقدام` برابر `تغییر` باشد و الگو منطبق شود، متن تغییر می‌کند و وضعیت برابر `mutated` ثبت می‌شود. اگر `اقدام` برابر `اعتبارسنجی` باشد، رفتار توقف یا فقط ثبت نتیجه به پارامتر `شیوه اجرا (enforcement)` بستگی دارد.

## تنظیمات

| فیلد | نوع | اجباری | توضیح |
| --- | --- | --- | --- |
| `patterns` | `string[]` | بله | فهرست Regexها. همه الگوها هنگام ذخیره اعتبارسنجی می‌شوند. |
| `redaction_text` | `string` | فقط برای تغییر متن، کاربردی است | متن جایگزین. اگر خالی باشد، عبارت  `[REDACTED]` جایگزین می‌شود. |

## نمونه اعتبارسنجی

```json
{
  "slug": "no-internal-ticket",
  "name": "No internal ticket IDs",
  "type": "regex",
  "operation": "validate",
  "enforcement": "audit",
  "enabled": true,
  "config": {
    "patterns": [
      "\\bTICKET-[0-9]{6}\\b"
    ]
  }
}
```

در این حالت، هربار که الگو منطبق شود، فقط درسوابق  ردیابی درخواست (trace)، به‌صورت `flagged` ثبت می‌شود، چون `شیوه اجرا (enforcement)` برابر `audit` است.

## نمونه تغییردادن

```json
{
  "slug": "mask-passwords",
  "name": "Mask password-like fields",
  "type": "regex",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "patterns": [
      "(?i)password\\s*[:=]\\s*\\S+"
    ],
    "redaction_text": "[SECRET]"
  }
}
```

## نمونه enforcement

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/mask-passwords"]}
```

برای خروجی non-stream:

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/no-internal-ticket"]}
```

## محدودیت‌ها

- Regexهای بیش از حد کلی می‌توانند false positive بسازند.
- Regexهای ضعیف می‌توانند false negative داشته باشند.
- این گاردریل فقط بخش‌های متنی داده‌های ارسالی (payload) را می‌بیند.
- برای گاردریل‌هایی که برای کنترل خروجی مدل وضع می‌کنید، و `stream: true` هستند استفاده نکنید؛ در حال حاضر پشتیبانی نمی‌شود.
