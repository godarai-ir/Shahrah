# Regex

گاردریل `regex` متن ورودی یا خروجی مدل را با یک یا چند الگوی Regex بررسی می‌کند. از این نوع وقتی استفاده کنید که عبارت ثابت کافی نیست و داده مورد نظر شما قالب مشخصی دارد؛ مثل شناسه مشتری، شماره پرونده، نام متغیر داخلی یا مقدارهایی شبیه `password=...`.

## چه زمانی استفاده کنید؟

از Regex برای این سناریوها استفاده کنید:

- متوقف‌کردن متن‌هایی که شامل شناسه یا عبارت داخلی سازمان هستند.
- ماسک‌کردن مقدارهایی که الگوی مشخص دارند.
- پوشش‌دادن داده‌های محرمانه‌ای که در [تشخیص Secret](/guardrails-secrets-detection) نیستند.
- کنترل ورودی مدل پیش از ارسال به ارائه‌دهنده، یا کنترل پاسخ پیش از تحویل به کاربر.

اگر فقط چند عبارت ثابت دارید، [عبارت‌های مسدود](/guardrails-keyword-blocklist) ساده‌تر است. اگر می‌خواهید فقط یک الگو را مستقیماً جایگزین کنید، [جایگزینی با Regex](/guardrails-regex-replace) را ببینید.

## رفتار اجرایی

این نوع از هر دو «نوع اقدام» پشتیبانی می‌کند:

| نوع اقدام | مقدار API | رفتار |
| --- | --- | --- |
| اعتبارسنجی | `validate` | اگر یکی از الگوها تطابق پیدا کند، نتیجه بررسی ناموفق می‌شود. اثر نهایی به «شیوه اعمال» بستگی دارد. |
| اصلاح محتوا | `mutate` | همه تطابق‌ها با «متن جایگزین» جایگزین می‌شوند و وضعیت `mutated` ثبت می‌شود. |

در حالت «اعتبارسنجی»، با «عبور همراه با نشانه‌گذاری» فقط وضعیت `flagged` ثبت می‌شود. با «عدم عبور و لاگ»، درخواست یا پاسخ متوقف می‌شود.

## تنظیمات

| عنوان | مقدار API | توضیح |
| --- | --- | --- |
| الگوهای Regex | `patterns` | هر خط یک Regex معتبر است. دست‌کم یک الگو لازم است. |
| متن جایگزین | `redaction_text` | فقط برای «اصلاح محتوا» استفاده می‌شود. اگر از API مقدار ندهید، موتور از `[REDACTED]` استفاده می‌کند. |

مقدار پیشنهادی «متن جایگزین» برابر `[***]` است. اگر می‌خواهید متن جایگزین دیگری ثبت شود، همان مقدار را وارد کنید.

## نمونه اعتبارسنجی

نمونه زیر شناسه‌هایی مثل `TICKET-123456` را فقط نشانه‌گذاری می‌کند و مسیر را متوقف نمی‌کند:

```json
{
  "slug": "no-internal-ticket",
  "name": "No internal ticket IDs",
  "type": "regex",
  "operation": "validate",
  "enforcement": "audit",
  "enabled": true,
  "config": {
    "patterns": [
      "\\bTICKET-[0-9]{6}\\b"
    ]
  }
}
```

پس از ذخیره، شناسه فنی این گاردریل `guardrails/no-internal-ticket` است.

## نمونه اصلاح محتوا

نمونه زیر مقدارهای شبیه رمز عبور را پیش از رسیدن به مدل ماسک می‌کند:

```json
{
  "slug": "mask-passwords",
  "name": "Mask password-like fields",
  "type": "regex",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "patterns": [
      "(?i)password\\s*[:=]\\s*\\S+"
    ],
    "redaction_text": "[***]"
  }
}
```

## نمونه استفاده

برای اجرای گاردریل روی ورودی مدل:

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/mask-passwords"]}
```

برای اجرای گاردریل روی پاسخ غیرجریانی مدل:

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/no-internal-ticket"]}
```

## بررسی نتیجه

اگر گاردریل در حالت «اصلاح محتوا» تطابق پیدا کند، وضعیت `mutated` ثبت می‌شود. اگر در حالت «اعتبارسنجی» تطابق پیدا کند، وضعیت با توجه به «شیوه اعمال» یکی از `flagged` یا `blocked` خواهد بود.

علت پیش‌فرض برای گاردریل اختصاصی Regex برابر `Sensitive pattern matched` است.

## محدودیت‌ها

- Regex معنای جمله را نمی‌فهمد و فقط الگو را بررسی می‌کند.
- الگوی بیش از حد کلی می‌تواند متن بی‌خطر را هم درگیر کند.
- الگوی ضعیف ممکن است شکل‌های متفاوت همان داده را تشخیص ندهد.
- فقط بخش‌های متنی بررسی می‌شوند.
- گاردریل خروجی با پاسخ جریانی پشتیبانی نمی‌شود.

## گام بعدی

- برای جایگزینی مستقیم یک الگو، [جایگزینی با Regex](/guardrails-regex-replace) را ببینید.
- برای داده شخصی رایج، [PII پایه](/guardrails-pii-redaction) را بخوانید.
- برای محدوده اجرا، [قابلیت‌ها و محدوده پشتیبانی گاردریل‌ها](/guardrails-capabilities) را مرور کنید.
