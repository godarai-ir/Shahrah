# گاردریل‌ها در گدارAI

گاردریل‌ `Guardrail` در گدارAI یک لایه کنترل روی متن ورودی و خروجی مدل است. اجرای عملی گاردریل‌ها در مسیر [Chat Completions](/supported-apis/chat-completions/overview) انجام می‌شود و انتخاب آن‌ها با سرآیندهای (header) درخواست کنترل می‌شود.

گاردریل‌ها دو کار اصلی انجام می‌دهند:

- `اعتبارسنجی (validate)`: متن را بررسی می‌کنند و در صورت تخطی، بسته به شیوه اعمال می‌توانند درخواست یا پاسخ را متوقف کنند.
- `تغییر (mutate)`: متن را پیش از ادامه مسیر تغییر می‌دهند؛ مثلا مقدار حساس را با `[REDACTED]` جایگزین می‌کنند.

## گاردریل‌های پشتیبانی‌شده

در گدارAI، گاردریل‌هایی که قابل تعریف و فعال‌سازی هستند این‌ها هستند:

| نوع | کاربرد | عملیات قابل استفاده | راهنما |
| --- | --- | --- | --- |
| `keyword_blocklist` | مسدودکردن عبارت‌های مشخص | فقط `اعتبارسنجی` | [عبارت‌های مسدود](/guardrails-keyword-blocklist) |
| `regex` | بررسی یا ماسک‌کردن الگوهای Regex سفارشی | `اعتبارسنجی` یا `تغییر` | [Regex](/guardrails-regex) |
| `secrets_detection` | تشخیص یا ماسک‌کردن توکن، کلید خصوصی و عبارت‌های محرمانه‌ی رایج | `validate` یا `mutate` | [تشخیص Secret](/guardrails-secrets-detection) |
| `basic_pii` | تشخیص یا ماسک‌کردن PII پایه مثل ایمیل، موبایل، عدد ۱۰ رقمی و کارت | `اعتبارسنجی` یا `mutate` | [PII پایه و Redaction](/guardrails-pii-redaction) |
| `regex_replace` | جایگزینی matchهای یک Regex | فقط `تغییر` | [جایگزینی با Regex](/guardrails-regex-replace) |
| `sentence_count` | محدودکردن تعداد جمله‌ها | فقط `اعتبارسنجی` | [تعداد جمله](/guardrails-sentence-count) |
| `word_count` | محدودکردن تعداد واژه‌ها | فقط `اعتبارسنجی` | [تعداد واژه](/guardrails-word-count) |
| `character_count` | محدودکردن تعداد نویسه‌ها | فقط `اعتبارسنجی` | [تعداد نویسه](/guardrails-character-count) |
| `json_schema` | اعتبارسنجی ساختار پایه JSON | فقط `اعتبارسنجی` | [JSON Schema](/guardrails-json-schema) |
| `json_keys` | کنترل کلیدهای سطح اول یک object JSON | فقط `اعتبارسنجی` | [کلیدهای JSON](/guardrails-json-keys) |
| `contains_code` | الزام یا منع وجود کد بر اساس fence و markerهای داخلی | فقط `اعتبارسنجی` | [تشخیص کد](/guardrails-contains-code) |
| `not_null` | ردکردن متن خالی، `null` یا `undefined` | فقط `اعتبارسنجی` | [مقدار غیرخالی](/guardrails-not-null) |
| `jwt_validation` | استخراج و اعتبارسنجی JWT | فقط `اعتبارسنجی` | [اعتبارسنجی JWT](/guardrails-jwt-validation) |
| `inline_image_urls` | دریافت URLهای تصویر داخل متن و تبدیل آن‌ها به data URL | فقط `mutate` | [Inline کردن URL تصویر](/guardrails-inline-image-urls) |

## تعریف گاردریل

هر گاردریل با این فیلدهای مشترک تعریف می‌شود:

```json
{
  "slug": "mask-contact",
  "name": "Mask contact data",
  "description": "Redact contact data before sending the prompt to the model.",
  "type": "basic_pii",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "redaction_text": "[REDACTED]"
  }
}
```

فیلدهای مهم:

- `slug`: یا شناسه فنی، شناسه‌ای قابل استفاده در بدنه درخواست است که باید ۲ تا ۹۶ کاراکتر انگلیسی باشد و می‌تواند شامل اعداد، و نویسه‌های زیرخط (ـ) و خط فاصله (-) باشد.
- `نوع`: یکی از انواع پشتیبانی‌شده در جدول بالا.
- `نوع اقدام`: یکی از `اعتبارسنجی` یا `تغییر`.
- `شیوه اعمال`: یکی از موارد `ثبت برای رسیدگی`، `انسداد` یا `انسداد و نادیده‌گرفتن خطا`.
- `فعال`: فقط گاردریل‌های فعال هنگام در پردازش درخواست حضور خواهند داشت.
- `تنظمیات`: تنظیمات اختصاصی همان نوع گاردریل.

## شیوه اعمال

`شیوه اعمال (enforcement)` مشخص می‌کند نتیجه گاردریل چه اثری روی درخواست یا پاسخ داشته باشد:

| مقدار | رفتار |
| --- | --- |
| `ثبت برای رسیدگی` | تخطی را نشانه‌گذاری می‌کند و آن را با وضعیت `flagged` ثبت می‌کند، اما مسیر را متوقف نمی‌کند. |
| `انسداد` | تخطی را متوقف می‌کند و خطا برمی‌گرداند. خطای اجرای خود گاردریل هم باعث توقف می‌شود. |
| `انسداد و نادیده گرفتن خطا` | تخطی را متوقف می‌کند، اما خطای اجرای گاردریل را نادیده می‌گیرد. |

برای گاردریل‌های `تغییر دهنده`، اگر مطابقت پیدا شود متن تغییر می‌کند و مورد بررسی شده، با status `mutated` ثبت می‌شود.

## انتخاب گاردریل در درخواست

برای اجرای گاردریل، شناسه فنی آن را در سرآیند (header) `x-godarai-guardrails` بفرستید. شناسه‌های فنی در سطح فضای کاری شما یکتا هستند و با الگوی `guardrails/<slug>` ساخته می‌شوند.

نمونه اجرای گاردریل روی ورودی:

```bash
curl -X POST "$GODARAI_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $GODARAI_API_KEY" \
  -H "Content-Type: application/json" \
  -H 'x-godarai-guardrails: {"llm_input_guardrails":["guardrails/mask-contact"]}' \
  -d '{
    "model": "openai:default:gpt-4o-mini",
    "messages": [{"role": "user", "content": "Email me at user@example.com"}]
  }'
```

نمونه اجرای گاردریل روی خروجی:

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/no-secrets"]}
```

برای سازگاری، کلیدهای `input_guardrails` و `output_guardrails` هم پذیرفته می‌شوند.

## گاردریل‌های عمومی

در پلتفرم چند گاردریل با شناسه‌های فنی پیش‌فرض آماده‌ی استفاده هستند. این گاردریل‌ها بدون آنکه نیاز باشد تا در فضای کاری خودتان، گاردریلی تعریف کنید،  قابلیت استفاده را دارند:

| شناسه فنی | رفتار |
| --- | --- |
| `guardrails/keyword-blocklist` | عبارت‌های پیش‌فرض مثل `ignore previous instructions`، `jailbreak`، `rm -rf` و `drop table` را مسدود می‌کند. |
| `guardrails/regex` | الگوی پیش‌فرض secret/token/password را با `[REDACTED]` جایگزین می‌کند. |
| `guardrails/secrets-detection` | secretهای رایج را با `[REDACTED]` جایگزین می‌کند. |
| `guardrails/basic-pii` | PII پایه را با `[REDACTED]` جایگزین می‌کند. |
| `guardrails/pii-redaction` | alias برای `basic_pii`. |
| `guardrails/pii-detection` | alias برای `basic_pii`. |

برای محیط عملیاتی بهتر است به‌جای تکیه بر گاردریل‌های عمومی، گاردریل اختصاصی فضای کاری خودتان با شناسه فنی و تنظیمات مشخص بسازید تا رفتار آن برای تیم شما قابل بازبینی باشد.

## حوزه اجرای گاردریل برای درخواست‌های ارسالی به مدل

سرآیند `x-godarai-guardrails-scope` مشخص می‌کند گاردریل‌های ورودی روی کدام پیام‌ها اجرا شوند:

| مقدار | رفتار |
| --- | --- |
| `all` | همه پیام‌های متنی از نقطه شروع انتخاب‌شده بررسی می‌شوند. مقدار پیش‌فرض است. |
| `last` | فقط آخرین پیام `کاربر` بررسی می‌شود. |

در پیام‌های مالتی‌مدال (multimodal)، فقط بخش‌های متنی با `type: "text"` بررسی یا تغییر داده می‌شوند.

## خروجی و استریمینگ

گاردریل خروجی بعد از دریافت پاسخ کامل ارائه‌دهنده اجرا می‌شود. در نسخه فعلی، ترکیب `stream: true` با `llm_output_guardrails` پشتیبانی نمی‌شود و درخواست با خطای `400` رد می‌شود.

گاردریل ورودی می‌تواند پیش از شروع استریم اجرا شود، چون قبل از ارسال بدنه درخواست به ارائه‌دهنده اعمال می‌شود.

## پاسخ خطا

اگر گاردریل با `انسداد` یا `انسداد و نادیده گرفتن خطا` مسیر را متوقف کند، پاسخ با قالب زیر برمی‌گردد:

```json
{
  "error": {
    "message": "Request blocked by GodarAI guardrail",
    "type": "guardrail_checks_failed",
    "code": "guardrail_blocked"
  },
  "guardrail_checks": {
    "llm_input_guardrails": [
      {
        "selector": "guardrails/no-injection",
        "status": "blocked",
        "operation": "validate",
        "enforcement": "enforce",
        "reason": "Keyword blocklist matched",
        "latency_ms": 0
      }
    ]
  }
}
```

برای خروجی، پیام خطا `Response blocked by GodarAI guardrail` است.

## مشاهده‌پذیری

نتیجه هر چک در ردیابی پیامها (trace) با نام‌هایی مثل `guardrail.llm_input_guardrails` و `guardrail.llm_output_guardrails` ثبت می‌شود و متادیتاهایی مثل شناسه فنی، وضعیت، نوع اقدام، شیوه اعمال، تاخیرو شرح علت دارد. برای تحلیل عملیاتی، این داده‌ها را کنار [Logs](/observability-logs) و [OpenTelemetry](/observability-opentelemetry) ببینید.

## از کجا شروع کنم؟

1. اگر فقط می‌خواهید عبارات ممنوع را متوقف کنید، [عبارت‌های مسدود](/guardrails-keyword-blocklist) را بخوانید.
2. اگر الگوهای داخلی سازمانی دارید، از [Regex](/guardrails-regex) شروع کنید.
3. اگر نگران توکن و کلید خصوصی هستید، [تشخیص Secret](/guardrails-secrets-detection) را فعال کنید.
4. اگر داده تماس یا شناسه‌های عمومی وارد پرامپت می‌شود، [PII پایه و Redaction](/guardrails-pii-redaction) را ببینید.
5. برای محدودیت طول، یکی از راهنماهای [جمله](/guardrails-sentence-count)، [واژه](/guardrails-word-count) یا [نویسه](/guardrails-character-count) را انتخاب کنید.
6. برای خروجی ساخت‌یافته، [JSON Schema](/guardrails-json-schema) و [کلیدهای JSON](/guardrails-json-keys) را مقایسه کنید.
