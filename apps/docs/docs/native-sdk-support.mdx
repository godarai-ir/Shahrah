# پشتیبانی از SDKهای بومی

برای اتصال محصول به گدارAI، مسیر پیشنهادی برای بیشتر تیم‌ها استفاده از APIها و SDKهای سازگار با OpenAI است. این مسیر ساده‌تر است، سریع‌تر آزمایش می‌شود و با بخش بزرگی از قابلیت‌های درگاه، مثل احراز هویت، کنترل مصرف و پایش، هماهنگ‌تر است.

SDK بومی ارائه‌دهنده زمانی مطرح می‌شود که محصول شما به قابلیت اختصاصی همان ارائه‌دهنده نیاز دارد یا از قبل روی آن SDK سرمایه‌گذاری کرده است. در این حالت، قبل از اتکا در محیط عملیاتی، باید مطمئن شوید مسیر بومی موردنظر در فضای کاری و استقرار شما فعال و مستند شده است.

## انتخاب پیش‌فرض: مسیر سازگار با OpenAI

اگر تازه می‌خواهید گدارAI را به محصول خود وصل کنید، از این مسیر شروع کنید:

1. SDK رسمی OpenAI یا درخواست HTTP سازگار با OpenAI را نگه دارید.
2. مقدار `base_url` را روی نشانی پایه گدارAI تنظیم کنید.
3. توکن دسترسی گدارAI را به‌جای کلید خام ارائه‌دهنده بفرستید.
4. مقدار `model` را از مدل مجاز یا مدل مجازی فضای کاری بردارید.

نمونه:

```python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_GODARAI_TOKEN",
    base_url="https://YOUR_WORKSPACE.godarai.ir/v1",
)

response = client.chat.completions.create(
    model="YOUR_MODEL_ID",
    messages=[{"role": "user", "content": "سلام"}],
)

print(response.choices[0].message.content)
```

این مسیر برای شروع، تست اتصال و بیشتر سناریوهای چندارائه‌دهنده انتخاب قابل اتکاتری است.

## چه زمانی SDK بومی را بررسی کنیم؟

SDK بومی ارائه‌دهنده زمانی ارزش بررسی دارد که یکی از این شرایط را دارید:

- قابلیت خاصی لازم دارید که در مسیر سازگار با OpenAI در دسترس نیست.
- شکل پاسخ بومی ارائه‌دهنده برای محصول شما مهم است.
- محصول شما از قبل با SDK همان ارائه‌دهنده ساخته شده و تغییر آن پرهزینه است.
- مسیر بومی در فضای کاری شما فعال شده و تیم شما آن را با ترافیک آزمایشی بررسی کرده است.

نمونه‌ها:

- استفاده از SDK بومی Anthropic برای الگوهایی که به قرارداد اختصاصی Claude وابسته‌اند.
- استفاده از SDKهای Google یا Vertex برای قابلیت‌هایی که در مسیر سازگار با OpenAI پوشش داده نشده‌اند.
- استفاده از SDKهای AWS Bedrock وقتی محصول شما از قبل در اکوسیستم AWS طراحی شده است.

این مثال‌ها به معنی فعال بودن همه مسیرهای بومی در همه استقرارها نیستند. وضعیت واقعی را در فضای کاری خودتان بررسی کنید.

## توصیه برای مهاجرت از اتصال مستقیم

اگر محصول شما امروز مستقیم به OpenAI یا ارائه‌دهنده دیگری وصل است:

1. ابتدا مسیر سازگار با OpenAI را با یک درخواست ساده تست کنید.
2. `base_url`، توکن و شناسه مدل را از تنظیمات بخوانید، نه از کد ثابت.
3. نتیجه را در «لاگ درخواست‌ها» یا «ردیابی درخواست‌ها» بررسی کنید.
4. سپس ترافیک یک مسیر کم‌ریسک را از گدارAI عبور دهید.
5. بعد از پایش خطا، هزینه و تأخیر، مسیرهای حساس‌تر را منتقل کنید.

این ترتیب کمک می‌کند مهاجرت قابل مشاهده و قابل بازگشت بماند.

## چه زمانی روی SDK بومی نرویم؟

اگر نیاز شما با APIهای سازگار با OpenAI پوشش داده می‌شود، SDK بومی معمولاً پیچیدگی بیشتری وارد می‌کند:

- قرارداد هر ارائه‌دهنده جدا می‌شود.
- عیب‌یابی و مقایسه رفتار بین ارائه‌دهنده‌ها سخت‌تر می‌شود.
- تغییر مدل یا ارائه‌دهنده به تغییرهای بیشتری در کد محصول وابسته می‌شود.
- تضمین یکسان بودن رفتار پایش و کنترل مصرف به بررسی بیشتری نیاز دارد.

## پرسش‌های پرتکرار

### آیا گدارAI فقط با SDK رسمی OpenAI کار می‌کند؟

خیر. گدارAI روی APIهای سازگار با OpenAI به‌عنوان مسیر عمومی و پیشنهادی تمرکز دارد، اما بسته به فضای کاری و استقرار، مسیرهای دیگری هم می‌توانند مطرح باشند. برای استفاده عملیاتی از SDK بومی، مسیر فعال محیط خودتان را تست کنید.

### اگر محصول من از قبل SDK بومی Anthropic یا Google دارد، باید همه چیز را عوض کنم؟

نه لزوماً. ابتدا بررسی کنید کدام بخش واقعاً به قرارداد بومی وابسته است. برای مسیرهایی که با قرارداد سازگار با OpenAI قابل انجام‌اند، مهاجرت ساده‌تر است. برای قابلیت‌های اختصاصی، مسیر بومی را جداگانه آزمایش کنید.

### بهترین مسیر برای شروع MVP چیست؟

برای بیشتر MVPها، مسیر سازگار با OpenAI بهترین شروع است: تغییر کمتر، تست سریع‌تر، و دسترسی بهتر به قابلیت‌های پایش و کنترل مصرف گدارAI.
