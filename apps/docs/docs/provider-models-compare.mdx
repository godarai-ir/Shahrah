# مقایسه مدل‌ها و هزینه استفاده

وقتی چند مدل به نیاز شما نزدیک‌اند، مقایسه مستقیم کمک می‌کند تصمیم را از حدس به چند معیار روشن تبدیل کنید: وضعیت، ارائه‌دهنده، نوع ورودی و خروجی، قیمت، پنجره زمینه، بیشینه خروجی، مجوز، مناطق، قابلیت‌ها و بنچمارک‌ها.

صفحه مقایسه برای انتخاب نهایی طراحی نشده که جای تست واقعی را بگیرد؛ برای کوتاه کردن فهرست گزینه‌ها و ساختن یک گفت‌وگوی دقیق‌تر داخل تیم است.

## شروع سریع مقایسه

1. از مسیر <a href="../catalog/models" data-noBrokenLinkCheck>فهرست مدل‌ها <span aria-hidden="true">↗</span></a> دو تا چهار مدل نزدیک به نیازتان را پیدا کنید.
2. از کارت مدل یا صفحه جزئیات، مدل‌ها را به مقایسه اضافه کنید.
3. صفحه <a href="../catalog/compare" data-noBrokenLinkCheck>مقایسه مدل‌ها <span aria-hidden="true">↗</span></a> را باز کنید.
4. اگر تعداد ستون‌ها زیاد است، گزینه `Only differences` را فعال کنید تا فقط تفاوت‌ها را ببینید.
5. برای اشتراک‌گذاری همان مقایسه، لینک دارای `ids` را برای هم‌تیمی‌ها بفرستید.

نمونه پیوند عمیق مقایسه:

در صفحه مقایسه، شناسه‌ها از `canonicalId` مدل‌ها می‌آیند. برای مثال `openai/gpt-4o` یک شناسه کامل مدل است.

## چه چیزهایی مقایسه می‌شود؟

| بخش | معیارها | کاربرد |
| --- | --- | --- |
| هویت | نام مدل، ارائه‌دهنده، خانواده مدل، وضعیت، تاریخ انتشار | برای تشخیص اینکه هر ستون دقیقاً به کدام مدل مربوط است. |
| قیمت | قیمت ورودی، قیمت خروجی، قیمت ورودی کش‌شده | برای تخمین هزینه سناریوهای پرترافیک و مقایسه مدل‌های نزدیک. |
| قابلیت‌ها | نوع ورودی، نوع خروجی، قابلیت‌ها، پارامترهای پشتیبانی‌شده | برای فهم اینکه مدل با نیاز فنی شما سازگار است یا نه. |
| محدودیت‌ها | پنجره زمینه و بیشینه توکن خروجی | برای اسناد طولانی، مکالمه‌های چندمرحله‌ای و پاسخ‌های بلند. |
| حکمرانی | متن‌باز بودن، رایگان بودن، مجوز، وجود مستندات | برای بررسی ریسک استفاده و شفافیت مدل. |
| مناطق و بنچمارک‌ها | مناطق و خلاصه بنچمارک‌ها | برای بررسی محدودیت منطقه‌ای و کیفیت نسبی. |

:::tip
اگر در یک مقایسه فقط قیمت را ببینید، ممکن است مدل کم‌کیفیت‌تر یا ناسازگارتر را انتخاب کنید. قیمت را کنار پنجره زمینه، نوع ورودی/خروجی، وضعیت، مستندات و تست واقعی بخوانید.
:::

## خواندن هزینه در مقایسه

در بیشتر سناریوهای متنی، هزینه از دو بخش اصلی می‌آید:

- ورودی: متن پرامپت، پیام‌های قبلی، متن ابزارها، داده‌های بازیابی‌شده و هر چیزی که مدل باید بخواند.
- خروجی: پاسخی که مدل تولید می‌کند.

برای سناریویی مثل پاسخ‌گویی پشتیبانی، اگر هر درخواست تاریخچه طولانی سفارش، چند پیام قبلی و توضیح کامل کالا را به مدل بدهد، هزینه ورودی مهم می‌شود. اگر مدل باید پاسخ بلند، گزارش یا متن چندبخشی تولید کند، هزینه خروجی هم وزن بیشتری پیدا می‌کند.

:::warning
برای مدل‌های تصویر یا صوت، صفحه مقایسه ممکن است همه جزئیات قیمت غیرمتنی را در یک نگاه نشان ندهد. بعد از مقایسه اولیه، بخش قیمت در صفحه جزئیات مدل را هم باز کنید.
:::

## الگوهای تصمیم‌گیری

| سناریو | معیارهای مهم‌تر |
| --- | --- |
| پشتیبانی مشتری با متن فارسی و تاریخچه سفارش | کیفیت پاسخ متنی، پنجره زمینه، هزینه خروجی، وضعیت `active`، امکان خروجی ساخت‌یافته. |
| خلاصه‌سازی تیکت‌های طولانی | پنجره زمینه، هزینه ورودی، بیشینه خروجی، پایداری وضعیت مدل. |
| تحلیل تصویر کالا یا رسید | ورودی تصویر، خروجی متن، مستندات رسمی، محدودیت حجم تصویر و هزینه غیرمتنی. |
| تولید تصویر برای کمپین | خروجی تصویر، قیمت تصویر، محدودیت‌های استفاده، کیفیت نمونه‌ها و وضعیت ارائه‌دهنده. |
| بردارسازی برای جست‌وجوی محصول | `mode` یا قابلیت embedding، هزینه ورودی، محدودیت ابعاد یا قرارداد API، پایداری مدل. |

## از مقایسه تا استفاده عملی

بعد از اینکه یک یا دو مدل مناسب‌تر پیدا کردید:

1. مدل را در فضای کاری خودتان از نظر دسترسی و حساب ارائه‌دهنده بررسی کنید.
2. اگر می‌خواهید شناسه مصرفی در کد پایدار بماند، [مدل مجازی](/virtual-model) بسازید.
3. درخواست آزمایشی را از مسیر API مناسب بفرستید.
4. هزینه و کیفیت واقعی را در [لاگ درخواست‌ها](/observability-logs) و [متریک‌های مدل](/observability-model-metrics) بررسی کنید.
5. برای محیط عملیاتی، [محدودیت نرخ](/guides/rate-limiting)، [محدودیت بودجه](/guides/budget-limiting) و [پایش هزینه](/cost-tracking) را تنظیم کنید.

:::tip
برای آزمایش منصفانه، چند درخواست واقعی از محصول خودتان را با همان پرامپت، همان داده ورودی و همان معیار ارزیابی روی مدل‌های منتخب اجرا کنید. مقایسه کاتالوگ شروع خوبی است؛ نتیجه عملی در داده واقعی شما کامل می‌شود.
:::

## پرسش‌های پرتکرار

### چند مدل را می‌توان هم‌زمان مقایسه کرد؟

صفحه مقایسه برای چند گزینه محدود طراحی شده است. انتخاب دو تا چهار مدل معمولاً خواناتر است و کمک می‌کند تفاوت‌ها گم نشوند.

### اگر یک مدل در لینک مقایسه پیدا نشود چه می‌شود؟

ممکن است شناسه کامل مدل اشتباه باشد، مدل دیگر در کاتالوگ فعال نباشد یا ارائه‌دهنده آن در دسترس نباشد. شناسه را از صفحه جزئیات مدل کپی کنید.

### آیا مقایسه کاتالوگ برای تخمین هزینه ماهانه کافی است؟

برای تخمین اولیه بله، اما برای بودجه‌ریزی بهتر باید حجم واقعی ورودی و خروجی، نرخ درخواست، کش، تلاش دوباره و رفتار کاربران محصول را هم وارد محاسبه کنید.
