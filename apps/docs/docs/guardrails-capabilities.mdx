# قابلیت‌ها و محدوده پشتیبانی Guardrails

این صفحه محدوده واقعی Guardrails در نسخه فعلی GodarAI را توضیح می‌دهد. اگر دنبال فهرست نوع‌های قابل استفاده هستید، اول [Guardrails](/guardrails) را ببینید.

## Guardrails در چه لایه‌ای عمل می‌کند؟

Guardrails در سطح gateway اجرا می‌شود؛ یعنی قبل از ارسال request به provider یا بعد از دریافت response از provider، متن قابل‌بررسی را ارزیابی یا تغییر می‌دهد.

در implementation فعلی، این اجرای gateway-level روی مسیر زیر فعال است:

```text
POST /v1/chat/completions
```

## ورودی و خروجی

Guardrails در دو hook اجرا می‌شود:

| hook | زمان اجرا | کلید header |
| --- | --- | --- |
| ورودی مدل | پیش از تماس با provider | `llm_input_guardrails` یا `input_guardrails` |
| خروجی مدل | بعد از پاسخ non-stream provider و قبل از تحویل پاسخ | `llm_output_guardrails` یا `output_guardrails` |

گاردریل ورودی می‌تواند payload را قبل از رسیدن به مدل تغییر دهد یا request را متوقف کند. گاردریل خروجی می‌تواند response را تغییر دهد یا جلوی برگشت پاسخ را بگیرد.

## متن قابل بررسی

در Chat Completions، گاردریل‌ها روی محتوای متنی پیام‌ها کار می‌کنند:

- اگر `content` رشته باشد، همان رشته بررسی می‌شود.
- اگر `content` چندبخشی باشد، فقط partهایی با `type: "text"` بررسی می‌شوند.
- تصویر، فایل، صوت و داده دودویی توسط این گاردریل‌های متنی تحلیل نمی‌شوند.

برای خروجی، متن `message.content` در choiceهای پاسخ بررسی یا تغییر داده می‌شود.

## scope ورودی

scope فقط روی گاردریل‌های ورودی اثر دارد:

| مقدار | رفتار |
| --- | --- |
| `all` | همه پیام‌های متنی از نقطه شروع انتخاب‌شده بررسی می‌شوند. مقدار پیش‌فرض است. |
| `last` | فقط آخرین پیام `user` بررسی می‌شود. |

نمونه:

```text
x-godarai-guardrails-scope: last
```

اگر مقدار دیگری بفرستید، request با خطای invalid guardrails scope رد می‌شود.

## Streaming

در نسخه فعلی:

- گاردریل ورودی با `stream: true` قابل استفاده است، چون قبل از تماس با provider اجرا می‌شود.
- گاردریل خروجی با `stream: true` پشتیبانی نمی‌شود.

اگر request شامل `stream: true` و `llm_output_guardrails` باشد، gateway با خطای `400` پاسخ می‌دهد.

## selectorهای tenant و builtin

selectorهای tenant-level از مقدار `slug` ساخته می‌شوند:

```text
guardrails/<slug>
```

علاوه بر آن، موتور پیش‌فرض چند selector آماده دارد:

- `guardrails/keyword-blocklist`
- `guardrails/regex`
- `guardrails/secrets-detection`
- `guardrails/basic-pii`
- `guardrails/pii-redaction`
- `guardrails/pii-detection`

برای رفتار قابل audit و قابل تنظیم، selector tenant-level انتخاب بهتری است.

## endpointهای دیگر

در مستندات API، endpointهای دیگری مثل Responses، Messages، Embeddings، image و audio هم وجود دارند؛ اما اجرای Guardrails در کد فعلی به handler مربوط به Chat Completions وصل شده است. بنابراین برای endpointهای دیگر نباید فرض کنید همین headerها حتما اعمال می‌شوند، مگر این‌که implementation آن مسیر هم اضافه شده باشد.

## Quick Reference

- مسیر فعال فعلی: `/v1/chat/completions`
- ورودی: پشتیبانی می‌شود
- خروجی non-stream: پشتیبانی می‌شود
- خروجی stream: پشتیبانی نمی‌شود
- multimodal: فقط بخش‌های متنی بررسی می‌شوند
- نوع‌های tenant-level قابل ذخیره: همه ۱۴ نوع فهرست‌شده در [Guardrails](/guardrails)

## FAQ

### آیا Guardrails روی همه endpointهای GodarAI کار می‌کند؟

خیر. در نسخه فعلی اجرای gateway-level آن روی Chat Completions فعال است.

### آیا تصویرهای داخل پیام multimodal بررسی می‌شوند؟

خیر. این گاردریل‌ها متنی هستند و فقط text partها را می‌بینند.

### آیا می‌توانم output guardrail را با streaming فعال کنم؟

خیر. فعلا response stream شده برای output guardrail پشتیبانی نمی‌شود.
