# الزام مقدار غیرخالی

`not_null` بررسی می‌کند متن قابل‌ارزیابی وجود داشته باشد و مقدار آن خالی یا null-like نباشد.

## چه زمانی استفاده کنیم؟

- جلوگیری از تحویل پاسخ خالی مدل
- ردکردن خروجی متنی `null` یا `undefined`
- اطمینان از وجود content متنی در choiceهای پاسخ

## رفتار اجرایی

این نوع فقط از `operation: "validate"` پشتیبانی می‌کند. check در این حالت‌ها ناموفق است:

- هیچ متن قابل‌ارزیابی وجود نداشته باشد.
- متن بعد از trim خالی باشد.
- متن بدون توجه به بزرگی حروف دقیقا `null` یا `undefined` باشد.

هر متن جداگانه بررسی می‌شود و وجود یک متن معتبر، متن خالی دیگر را جبران نمی‌کند.

## تنظیمات

این گاردریل config اختصاصی ندارد و `config` باید object خالی باشد.

## نمونه تعریف

```json
{
  "slug": "non-empty-response",
  "name": "Require response content",
  "type": "not_null",
  "operation": "validate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {}
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_output_guardrails":["guardrails/non-empty-response"]}
```

## محدودیت‌ها

- رشته‌هایی مثل `N/A`، `{}`، `[]` یا `"null"` خالی محسوب نمی‌شوند.
- کیفیت یا معنای پاسخ بررسی نمی‌شود.
- فقط content متنی بررسی می‌شود؛ tool call بدون content متنی ممکن است به‌عنوان پاسخ خالی دیده شود.
- این نوع فقط tenant-level است و output streaming را پشتیبانی نمی‌کند.
