# درون‌خطی‌سازی تصویر

گاردریل `inline_image_urls` آدرس‌های HTTP و HTTPS داخل متن را دریافت می‌کند و اگر پاسخ یک تصویر معتبر باشد، آن آدرس را با data URL مبتنی بر Base64 جایگزین می‌کند.

از این نوع وقتی استفاده کنید که متن کاربر یا سیستم شامل URL تصویر است و می‌خواهید تصویر پیش از ارسال به مدل، در خود متن درون‌خطی شود.

## چه زمانی استفاده کنید؟

از این گاردریل برای این کارها استفاده کنید:

- تبدیل URL تصویر داخل متن به مقداری مثل `data:image/png;base64,...`.
- حذف وابستگی ارائه‌دهنده مدل به دسترسی مستقیم به دامنه تصویر.
- محدودکردن دامنه، اندازه و مهلت دریافت تصویر پیش از ادامه مسیر.

## رفتار اجرایی

این نوع فقط از «اصلاح محتوا» (`operation: "mutate"`) پشتیبانی می‌کند. گدارAI هر URL با `http` یا `https` را در متن پیدا می‌کند، تصویر را دریافت می‌کند و این موارد را بررسی می‌کند:

- URL شامل username یا password نباشد.
- اگر «دامنه‌های مجاز» وارد شده است، دامنه URL دقیقاً در همان فهرست باشد.
- به‌صورت پیش‌فرض، دامنه به IP خصوصی، loopback، link-local یا unspecified resolve نشود.
- پاسخ HTTP موفق باشد و `Content-Type` آن با `image/` شروع شود.
- اندازه بدنه پاسخ از «حداکثر حجم تصویر» بیشتر نباشد.

همین کنترل‌ها روی redirectها هم اعمال می‌شوند. اگر تبدیل انجام شود، وضعیت `mutated` و علت `Image URLs converted to inline data` ثبت می‌شود.

## تنظیمات

| عنوان | مقدار API | توضیح |
| --- | --- | --- |
| حداکثر حجم تصویر | `max_bytes` | حداکثر اندازه هر تصویر بر حسب بایت. مقدار پیش‌فرض `1048576` است. |
| دامنه‌های مجاز | `allowed_hosts` | هر خط یک دامنه مجاز است. بدون wildcard بررسی می‌شود. اگر خالی بماند، همه دامنه‌های عمومی مجازند. |
| مهلت زمانی (میلی‌ثانیه) | `timeout_ms` | مهلت دریافت هر URL. مقدار پیش‌فرض `3000` است. |
| اجازه به آدرس‌های شبکه خصوصی | `allow_private_networks` | پیش‌فرض خاموش است. فقط در شبکه کنترل‌شده فعال کنید. |

## نمونه تعریف

```json
{
  "slug": "inline-cdn-images",
  "name": "Inline trusted CDN images",
  "type": "inline_image_urls",
  "operation": "mutate",
  "enforcement": "enforce",
  "enabled": true,
  "config": {
    "max_bytes": 1048576,
    "allowed_hosts": ["images.example.com"],
    "timeout_ms": 3000,
    "allow_private_networks": false
  }
}
```

## نمونه استفاده

```text
x-godarai-guardrails: {"llm_input_guardrails":["guardrails/inline-cdn-images"]}
```

اگر متن ورودی این باشد:

```text
این تصویر را بررسی کن: https://images.example.com/chart.png
```

پس از اصلاح محتوا، URL تصویر با مقداری که با `data:image/png;base64,` شروع می‌شود جایگزین خواهد شد.

## رفتار خطا

اگر دریافت تصویر، بررسی دامنه، نوع محتوا یا محدودیت اندازه ناموفق باشد:

- با «عدم عبور و لاگ»، درخواست یا پاسخ متوقف می‌شود.
- با «عبور همراه با نشانه‌گذاری»، خطا در نتیجه بررسی ثبت می‌شود و متن اصلی ادامه پیدا می‌کند.
- با «عدم عبور - بدون لاگ»، خطای اجرای خود گاردریل مسیر را متوقف نمی‌کند.

## محدودیت‌ها و نکات امنیتی

- این گاردریل همه URLهای HTTP(S) داخل متن را نامزد تصویر فرض می‌کند. URL یک صفحه وب معمولی می‌تواند خطای `URL did not return an image` بسازد.
- فقط URL داخل محتوای متنی را تغییر می‌دهد و فیلد ساخت‌یافته `image_url` در پیام چندبخشی را بازنویسی نمی‌کند.
- دریافت تصویر در زمان درخواست انجام می‌شود و حافظه نهان داخلی ندارد؛ تعداد URLها روی زمان پاسخ اثر مستقیم دارد.
- برای محیط عملیاتی، «دامنه‌های مجاز» را محدود کنید.
- «اجازه به آدرس‌های شبکه خصوصی» را فقط وقتی فعال کنید که شبکه و مقصدها کاملاً تحت کنترل شما هستند.
- بررسی تصویر بودن بر اساس هدر `Content-Type` است، نه تحلیل کامل فایل تصویر.
- گاردریل آماده برای این نوع وجود ندارد؛ باید گاردریل اختصاصی بسازید.
